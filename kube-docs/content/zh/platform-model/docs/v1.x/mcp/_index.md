## 什么是 MCP

Model Context Protocol（MCP）是一项开放协议，旨在标准化大型语言模型（LLMs）与外部数据源和工具的交互方式。它被比喻为"AI 应用的 USB-C 端口"——通过提供统一接口，简化 AI 模型与各种工具、数据库和服务的连接，解决传统 M×N 集成问题。

## 主要优势

- **门槛降低**：显著降低了大模型调用外部工具、软件和接口的复杂性。
- **生态系统扩展**：越来越多的软件和工具供应商加入 MCP 生态，丰富了可供 AI 模型使用的资源。
- **标准化对接**：提供统一接口，使大型语言模型能够轻松连接和使用不同的数据源和工具。

## 平台中的 MCP 仓库

平台提供 MCP 仓库（MCP Hub），用于托管和分享符合 MCP 标准的工具服务。开发者可以：

- 创建 MCP 服务仓库，发布自己开发的 MCP 工具。
- 浏览和获取社区开放的 MCP 工具服务。
- 将 MCP 工具部署为可运行的用户空间服务。

## MCP 应用部署

平台支持将 MCP 服务部署为独立的用户空间（Space），提供标准化的 API 接入点，供 AI 客户端（如支持 MCP 的智能体框架）直接调用。

## 查看 MCP 协议

进入任一 MCP 仓库详情页的 **协议** Tab，可以查看该服务实际对外提供的**工具**、**提示词**与**资源**，以及运行它所需的环境变量。

协议内容由平台**主动探测**服务本身得到，而不是解析仓库里的源码：平台与运行中的服务做一次 MCP 握手，读取它的 `tools/list`、`prompts/list`、`resources/list`，因此展示的就是该服务真实承诺的能力，包含随环境变化的部分。

探测是自动的，无需手动触发：

- **部署成功后**：空间进入运行状态时，平台自动探测一次。
- **定时补偿**：平台还会周期性检查「正在运行但协议仍为空」的服务并补齐，用于兜住部署时未探测成功的少数情况。周期默认 10 分钟，可由管理员通过环境变量 `STARHUB_SERVER_MCP_SCAN_SCHEMA_REFRESH_INTERVAL` 调整（设为非正值即关闭）。

因为协议来自运行中的服务，**尚未部署的 MCP 服务在协议 Tab 中为空**，并会提示部署后自动获取。工具页（**MCP 工具**，`/mcp/servers/tools`）展示的是同一份数据的另一种视图：按工具逐条列出，并可点进工具详情查看输入参数。

协议内容较长时，页面左侧会常驻一份目录（服务器配置 / 提示词 / 资源 / 工具），点击即可在**当前页**滚动到对应区块，方便在工具较多时快速定位。

## 管理后台

管理员可在 **MCP 管理**（`/admin_panel/mcps`）搜索 MCP 仓库，查看工具数、可见性与权重，进入详情设置权重或改可见性，并支持单条 / 批量删除。

## 典型应用场景

- **数据库查询**：通过 MCP 让大模型直接查询内部数据库。
- **文件读写**：让大模型读取或写入本地/远程文件系统。
- **API 调用**：将企业内部 API 封装为 MCP 工具，供大模型调用。
- **代码执行**：提供代码沙箱执行能力给大模型。
