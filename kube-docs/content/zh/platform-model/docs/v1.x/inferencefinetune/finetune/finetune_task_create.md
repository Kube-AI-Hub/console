## 微调实例与微调任务的区别

平台提供两种微调形态，选择哪一种取决于你的使用方式。

| | 微调实例 | 微调任务 |
|---|---|---|
| 运行方式 | 常驻 Pod，创建后需要手动启动 | 提交即运行，跑完自动结束 |
| 使用界面 | 内置 Jupyter 与训练框架 Web 界面 | 无界面，按表单参数直接训练 |
| 算力释放 | 需要手动停止，否则一直占用 | 任务结束后自动释放 |
| 适用场景 | 需要交互式调试、反复试参数 | 参数已确定，跑一次拿结果 |
| 入口 | 模型详情页「微调实例」按钮 | 训练评测与开发 → 微调任务 → 新建任务 |

{{< notice tip >}}
如果只是想跑一次训练拿结果，用微调任务更省事——不用记得回来关掉算力。
如果还在调参、需要看训练过程中的实时曲线，用微调实例。
{{< /notice >}}

## 创建入口

在左侧导航进入 **训练评测与开发**，选择 **微调任务**，点击右上角 **新建任务**。

## 配置参数说明

填写以下配置后点击 **提交任务**：

| 参数 | 说明 |
|------|------|
| **基座模型** | 要微调的模型，支持搜索选择。选中后框架候选会按该模型刷新 |
| **训练数据集** | 训练用的数据集，支持搜索选择 |
| **微调框架** | 运行时框架，如 MS-Swift。下拉只列微调类框架，不含推理引擎 |
| **算力规格** | 任务运行的 GPU 规格。页面显示各档显存；低于模型推荐值时标注**显存不足** |
| **训练轮数** | 训练 epoch 数，默认 1 |
| **学习率** | 默认 0.00001 |
| **训练命令** | `sft`（指令微调）、`rlhf`（偏好对齐）或 `pt`（继续预训练） |

{{< notice note >}}
提交后立即开始训练，**不能暂停或续跑**。任务失败需要重新提交；算力规格在提交后不可更改。
{{< /notice >}}

## 任务执行过程

任务分为三个阶段，详情页可以看到每一步的进度：

1. **下载**：拉取基座模型与数据集。平台托管的模型从共享缓存读取，不需要重复下载。
2. **训练**：按所选框架与超参训练，这一阶段占用 GPU。
3. **上传**：合并 LoRA 权重并导出到模型库，完成后任务结束、算力释放。

## 查看任务状态

在 **微调任务** 列表可以看到所有任务及其状态：

| 状态 | 含义 |
|------|------|
| 排队中 | 已提交，等待算力调度 |
| 运行中 | 正在下载、训练或上传 |
| 已完成 | 训练结束，产物已导出 |
| 失败 | 任务中止，列表与详情页会给出失败原因 |

点击任意一行进入任务详情，可以看到三段进度、各阶段日志，以及完成后的产物入口。

## 常见问题

**提交后提示资源不足**：集群当前没有可用的 GPU 规格。可以换一个规格，或等推理实例释放算力后再提交。

**任务失败但看不到原因**：详情页会展示失败原因与失败阶段。如果原因是显存不足，改用更大的规格重新提交。

**训练完成但看不到产物**：确认任务状态是**已完成**而非**失败**。产物导出失败时任务会标记为失败，不会给出结果链接。

**能不能改成多卡训练**：可以，在算力规格里选择多卡规格。多卡会按数据并行运行。
