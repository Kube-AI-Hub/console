创建评测时，主流程是选模型、数据集、区域资源和评测框架。框架版本确定后，页面可能再给出三类可选项。不改则沿用框架与数据集的默认协议。

## 参数分三类

| 位置 | 参数 | 改了会怎样 |
|------|------|------------|
| 折叠 **评测框架参数** | 当前评测框架暴露的 engine_args（如 few-shot 条数、生成长度上限） | 改变推理或评测运行方式，**不改**评分公式 |
| 折叠 **vLLM 参数** | 评测走 vLLM 后端时出现（如 dtype、最大生成长度） | 只影响推理引擎，不改指标定义 |
| 折叠 **高级选项** | **Prompt 模版**、**打分插件** | Prompt 改协议，分数不可与官方榜单横比；插件改用哪套框架原生指标 |

不要用 Prompt 去「换指标」，也不要用框架 / vLLM 参数去「改准确率定义」。

## 评测框架参数与 vLLM 参数

这两块只在所选框架版本声明了 engine_args 时出现，字段由镜像配置决定。

常见用途：

- 控制 batch、最大生成长度、dtype，避免 OOM 或截断。
- 调整框架运行开关，而不改题干和计分。

未改动的项不会写入提交体，任务使用框架默认值。已改的项会进入评测报告的配置快照。

## 高级选项：Prompt 与打分插件

默认折叠。打开后按**已选框架 + 数据集**填入推荐目录中的默认模版和插件。切换框架或数据集会重新加载默认值。

| 情况 | 建议 |
|------|------|
| 系统推荐集、要和论文 / 榜单比 Accuracy | **不要改** Prompt；指标保持框架默认 |
| 自选业务集、对齐线上 system prompt、协议消融、LLM Judge | 再改 Prompt 或打分插件 |

覆盖后分数只能当「本任务自定义协议」。所选模版和插件会写入报告快照。插件必须与当前框架一致，不能跨 OpenCompass / lm-evaluation-harness / EvalScope 混用。

自选数据集若不在推荐目录中，高级选项默认为空，语义仍是框架对该文件布局的默认协议，可再选手动兼容的模版和插件。

更细的「何时改 Prompt」见[打分插件与 Prompt 模版](./evaluation_scoring_plugins)；指标对照见[指标配置](./evaluation_metrics_config)。

## 报告里能看到什么

详情页 **评测报告** 展示配置快照（模型 / 数据集 revision、框架、Prompt、插件、engine_args）、样本覆盖率和失败样例。任务运行中也可以打开详情查看配置和状态；分数在成功后写入。

`report_id` 与评测 `task_id` 相同。后续对比或发布门禁应绑定该 id，而不是改历史模版后重算同一任务。
