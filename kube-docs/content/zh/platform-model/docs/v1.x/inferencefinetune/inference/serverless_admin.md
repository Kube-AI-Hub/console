## 管理入口

以平台管理员身份登录，进入 **管理员后台 → 算力资源管理 → 公共推理服务**。页面分为两个页签：

| 页签 | 用途 |
|------|------|
| **本地部署** | 管理已在集群内部署的共享推理服务：查看详情、编辑、停止 / 重启、运行日志 |
| **云端 API** | 登记外部厂商通道，使云端模型出现在用户侧的公共推理列表中 |

用户侧列表会合并两类已启用的服务。

## 本地部署

本地公共推理从模型仓库发起，而不是在本列表中「新建」：

1. 打开目标模型，由管理员创建 Serverless / 公共推理部署。
2. 填写集群、部署名称、ENV、最小 / 最大副本、资源规格和运行时框架。
3. 部署成功后出现在 **本地部署** 页签，并同步到用户侧 **公共推理服务**。

## 云端 API 通道

在 **云端 API** 页签点击**新建云端 API**，填写：

| 参数 | 说明 |
|------|------|
| **名称** | 通道显示名称 |
| **厂商类型** | OpenAI、Azure、Aliyun DashScope、DeepSeek、Moonshot、Zhipu、SiliconFlow、VolcEngine、OpenRouter 或 Custom |
| **Base URL** | 上游兼容接口根地址，选择厂商后会填入常用默认值 |
| **API Key** | 写入 `Authorization: Bearer`；Azure 使用 `api-key`。编辑时留空则保留原密钥 |
| **模型列表** | 平台模型 ID，回车添加。用户请求和公共推理列表都使用这些 ID |
| **模型映射** | 可选 JSON 对象。键必须已在模型列表中，值是上游真实 ID。未写出的 ID 原样转给上游 |
| **启用** | 关闭后用户列表和网关都不会再使用该通道 |

示例：平台对外 ID 为 `kimi`，上游为 `kimi-k3` 时，模型列表填 `kimi`，映射填 `{"kimi":"kimi-k3"}`。用户请求 `model=kimi`，网关转发给上游 `kimi-k3`。

保存后可做**连通性测试**。只有**启用**的通道会出现在公共推理列表，并经 `/aigateway` 转发。

{{< notice note >}}
云端通道独立于平台模型仓库，不必先创建同名仓库。密钥只保存在服务端，不会回显到表单。
{{</ notice >}}
