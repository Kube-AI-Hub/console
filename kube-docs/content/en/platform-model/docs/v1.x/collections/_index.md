## What is a collection

A collection gathers **public projects** such as models, datasets, code, and user spaces into one topic for sharing and browsing.

A collection is **not a Git repository**: it stores only metadata and project references, so it takes no storage and needs no file upload.

A typical use: gather the model, dataset, and inference code for one business flow into a "customer service solution" collection and share it with colleagues or customers.

## List

Go to **Data & Assets → Collections** (`/collections`).

- Cards show a **theme colour, title, and summary**.
- The top search filters by name keyword, and **+ New** creates one.
- Click a card for the detail page.

## Creating a collection

| Field | Description |
|-------|-------------|
| Name | 2–70 characters, **cannot be changed after creation** |
| Summary | One sentence describing what this topic contains |
| Theme colour | Light purple / light green / light orange |

## Detail

A collection detail page has two tabs:

- **Projects**: lists the models, datasets, code, and user spaces in the collection. An empty collection offers "Add project".
- **Settings**: change the summary and theme colour.

Two ways to add projects:

1. Add them from the **Projects** tab of the collection detail page.
2. Use **Add to collection** on any repository detail page and pick the target collection.

Removing a project happens in the project list on the collection detail page as well.

## Visibility

A collection holds **public projects only**. A project's own visibility does not change because it joined a collection: opening the project still follows that project's own permissions.
