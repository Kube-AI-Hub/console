# 工作台（L2）

工作台是进入项目控制台的入口：它把「企业空间 → 项目（属于某个集群）」这条关系摆出来，
并把用户带到对应项目的页面。顶部「工作台」入口必须真的到达本页。

## 概述

平台用户的日常工作从工作台开始：先看自己在哪些企业空间里，再选一个项目进去。项目控制台
本身需要一个项目，所以「工作台 = 项目控制台」是不成立的——入口页必须先把项目选出来。

## 用户故事

### US1 - 从工作台进入一个项目 (Priority: P1)

作为 **平台用户**，我希望 **在工作台看到我所在企业空间的项目并点进去**，以便 **不用手拼 URL 也能开始工作**。

**Independent Test**：点击顶部「工作台」，页面列出企业空间与项目；点任一项目进入该项目控制台，
页头、侧栏与三级上下文栏同时在位。

## 验收场景

- **AC-FULL-KUBE-FRONTEND-WORKBENCH-01** — 已登录，当打开工作台并进入一个项目，则工作台列出企业空间与项目，且项目控制台的侧栏与上下文栏都在位。

## 设计目标

一个页面回答「我在哪些企业空间、能进哪些项目」，并且一次点击就到。

## 约束与边界

- 只列归属企业空间的命名空间作为项目。
- 项目按 (集群, 命名空间) 唯一。

## UI 交互设计

顶部标题与说明；按集群分节，节内按企业空间列出项目胶囊；点击进入项目控制台。

## 页面结构

- 页头：`工作台` / 说明
- 集群分节（`workbench:cluster:<c>`）
  - 企业空间块（`workbench:workspace:<ws>`）
    - 项目胶囊（`workbench:project:<cluster>/<ns>`）

## 异常态

- 集群或企业空间读取失败：错误面板 + 重试。
- 无项目：空态 + 「前往平台管理」。

## 功能需求

- **FR-FULL-KUBE-FRONTEND-WORKBENCH-01** — 工作台列出企业空间与其项目，可进入项目控制台。

## 成功标准

- **SC-FULL-KUBE-FRONTEND-WORKBENCH-01** — 从顶部入口到项目页只需一次点击，且三处结构齐全。

## 明确不做

- 工作台仪表盘统计、在工作台创建项目。

## 假设

- 项目与企业空间的归属由命名空间标签决定。
