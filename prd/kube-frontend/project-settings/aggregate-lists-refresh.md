# 聚合型列表刷新（L3）

[子模块需求](./_index.md)

## 概述

有一类列表的行数据不是由自己的一次查询得来：集群资源监控页把 pod 指标与 ReplicaSet 归属合成一张表；企业空间用户组的成员表与左树来自两个查询；企业空间成员详情页的资源表由四个查询拼成。它们此前都没有刷新入口，读者只能退出重进。

## 用户故事

### US1 - 聚合表也能重读 (Priority: P1)

作为 **集群或企业空间管理员**，我希望 **在这些聚合列表上直接刷新**，以便 **在看板上确认刚发生的调度/授权变化，而不必退出页面**。

**Independent Test**：打开集群资源监控页点击「刷新」，pod 指标请求重新发起；打开企业空间用户组页，成员表刷新后行数与接口一致；成员详情页的「项目」表有刷新入口。

## 验收场景

- **AC-L3-KUBE-FRONTEND-PROJECT_SETTINGS-AGGREGATE_LISTS_REFRESH-01** — 已知集群资源监控页与企业空间成员详情页均已加载，则两处都有「刷新」入口且空闲时可用；当点击刷新，则对应的**全部**来源查询重新发起（资源监控：指标与归属两个查询；成员详情：页面上的四个查询一起失效并重取）；句柄分别为 `cluster-resource-monitor:refresh` 与 `workspace-member-<tab>:refresh`。企业空间用户组的成员表在没有任何用户组时不会渲染表格（空态给出的是「先创建一个用户组」的指引），其刷新随该表一起在下次单元交付。

## 设计目标

1. 聚合表的刷新必须覆盖它显示的所有来源，否则刷新后表格仍是半新半旧。
2. 忙碌状态取所有来源的并集。

## 约束与边界

- 资源监控页两个页签共用一个 schema，刷新重读两个来源。
- 成员详情的表拿不到查询本身（行由父级传入），因此刷新用 `invalidateQueries()` 让该页所有查询失效重取。

## UI 交互设计

- 工具栏右侧「刷新」按钮；忙碌时禁用，返回后恢复。

## 文案与校验

- 文案取 `common.refresh`；无表单，不做输入校验。

## 边界情况

- 指标接口不可用时表格降级为 `-`，刷新仍可点（用于确认接口是否恢复）。
- 任一来源失败：刷新后仍显示已成功部分，并保留错误提示。

## 假设

- 三处的来源查询都在同一页面内，可被统一触发。

## 明确不做

- 把聚合表拆成多个独立列表（会改变页面结构，另议）。
- 定时轮询与 watch（R-27）。

## 功能需求

- **FR-L3-KUBE-FRONTEND-PROJECT_SETTINGS-AGGREGATE_LISTS_REFRESH-01** — 三处聚合列表的刷新与忙碌状态。

## 成功标准

- **SC-L3-KUBE-FRONTEND-PROJECT_SETTINGS-AGGREGATE_LISTS_REFRESH-01** — 刷新后聚合表的所有来源都是最新一次请求的结果。
