# 项目概览（L3）

[子模块需求](./_index.md)

## 概述

项目作用域的落地页：项目是谁建的、别名与描述、生效中的资源配额（已用 / 硬限）与限额范围，以及进入常用页面的快捷入口。

老 console 的项目概览还有「用量排行」和「应用」两部分：前者依赖监控区间查询，后者依赖 openpitrix 模块，本集群均不可用，因此不在本页。

## 用户故事

### US1 - 打开项目先看清它的边界 (Priority: P1)

作为 **项目成员**，我希望 **进入项目先看到它的配额与限额**，以便 **在申请资源前知道自己还有多少余量**。

**Independent Test**：打开项目概览，核对配额条数与 resourcequotas 的 hard 键数一致；没有配额时显示空态。

## 验收场景

- **AC-L3-KUBE-FRONTEND-PROJECT_SETTINGS-OVERVIEW-01** — 已知项目存在，当打开项目概览，则显示名称、别名、创建者、创建时间与描述；配额区块逐条显示「已用 / 硬限」与占比条，条数等于该项目 resourcequotas 的 hard 键数（没有配额时显示空态）；限额范围区块列出 limitranges（没有时显示空态）；快捷入口包含容器组、部署、配置字典、存储卷、项目成员，链接指向对应页面。

## 设计目标

1. 一屏回答「这个项目是什么、还有多少余量、下一步去哪」。
2. 配额用「已用 / 硬限 + 占比」表达，而不是只给数字。

## 约束与边界

- 项目信息与配额读 `projectInfoApi`（namespace 对象 + `/api/v1` 的 resourcequotas）。
- 限额范围读 `/api/v1/namespaces/<ns>/limitranges`（核心 API，资源代理不提供该资源）。
- 只读。

## UI 交互设计

- 顶部：别名优先的标题 + 一句说明。
- 基本信息两列；描述单独一行。
- 配额：每行资源名 + 已用/硬限 + 进度条（≥90% 转危险色）。
- 限额范围、快捷入口各一块。

## 文案与校验

- 无配额：该项目没有设置资源配额。无限额：该项目没有限额范围。
- 空值统一 `-`。

## 边界情况

- 配额值为 0 或无法解析：占比按 0 处理，不显示 NaN。
- 限额范围读取失败：只该区块降级。

## 明确不做

- 用量排行（需要监控区间查询）。
- 应用列表（依赖 openpitrix 模块，本集群关闭）。
- 配额编辑：已有项目设置的配额编辑入口。
- 概览页的「如何邀请成员 / 如何设置网关」提示卡片：这类引导卡只在首次使用时有价值，之后长期占据首屏；对应能力在成员页与网关页都有入口，概览页不再重复。

## 假设

- 配额对象与限额范围都在项目命名空间内，且核心 API 可读。

## 验收用例

- `TC-L3-KUBE-FRONTEND-PROJECT_SETTINGS-OVERVIEW-01`

## 功能需求

- **FR-L3-KUBE-FRONTEND-PROJECT_SETTINGS-OVERVIEW-01** — 展示项目基本信息与配额使用。
- **FR-L3-KUBE-FRONTEND-PROJECT_SETTINGS-OVERVIEW-02** — 展示限额范围与快捷入口。

## 成功标准

- **SC-L3-KUBE-FRONTEND-PROJECT_SETTINGS-OVERVIEW-01** — 配额条数与 hard 键数一致；快捷入口链接可达。
