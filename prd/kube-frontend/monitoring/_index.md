# 监控告警（L2）

[上级模块](../_index.md)

项目内的告警历史与告警规则。老 console 把它们放在侧栏「监控告警」分组；本模块收进同一个功能区。

## 概述

- **路由**：`/kube-frontend/:workspace/clusters/:cluster/projects/:namespace/{alerts,alertingrules}`
- **谁用**：项目运维，值班时看「现在有没有在告警」，平时看「规则开了哪些」。
- **做哪几步**：打开告警消息 → 看状态与级别 → 必要时删除历史；切到告警策略 → 看启用状态与规则数。
- **看到什么**：两张列表；消息行两行（消息内容 + 监控目标），策略行两行（名称 + 描述）。

## 用户故事

### US1 - 在告警与策略之间切换而不离开当前项目 (Priority: P1)

作为 **项目运维**，我希望 **用页签切换两张表**，以便 **不必回侧栏**。

**Independent Test**：从告警消息切到告警策略，核对页签高亮与工作区栏项目不变，且没有整页刷新。

## 验收场景

- **AC-FULL-KUBE-FRONTEND-MONITORING-01** — 已知已登录且有项目权限，当在两个页签之间切换，则每次都显示对应列表或空态，页签高亮跟随，且切换不产生文档请求。

## 设计目标

1. 告警数据走它自己的 kapis 组，不走通用资源代理。
2. 模块未安装时显示空态，不显示错误页。

## 约束与边界

- 读 `/kapis/alerting.kubesphere.io/v2beta1/...`：项目告警消息 `namespaces/<ns>/alerts`、集群级 `clusteralerts`、内置 `globalalerts`；告警消息只读（聚合 API 无 item 删除路由）；策略可启停，项目级自定义策略可创建/编辑/删除（见 [alerts-write.md](./alerts-write.md)），内置与集群级策略只读；行操作「详情」打开独立详情页（规则 + 告警消息，见 [rules.md](./rules.md)）。
- 作用域只从路由参数派生。

## UI 交互设计

工作区栏 + 区域页签（告警消息、告警策略）；消息行操作「详情」（抽屉，只读）；策略行操作「详情」「启用/停用」「编辑」「删除」（后两者只对项目级自定义策略且 SSAR 允许时显示），列表主操作「创建策略」（SSAR 允许时出现）。详情页分「基本信息 → 规则 → 告警消息」三段。

## 页面结构

| 页签 | 路由 |
|---|---|
| 告警消息 | `…/alerts` |
| 告警策略 | `…/alertingrules` |

## 文案与校验

- 消息列：消息、状态、级别、触发时间。
- 策略列：名称、策略状态、规则数、最近检测。
- 状态：告警中 / 待触发 / 已恢复；级别：严重 / 警告 / 提示。

## 边界情况

- 告警模块未安装：接口返回 200 空响应体，页面显示空态。
- 告警消息已被删除：列表刷新后不再出现。

## 异常态

- 加载中：表格骨架。
- 空：空态标题与说明，不渲染表头；模块未安装时也走这条。
- 失败：错误面板 + 重试（仅真正的失败，空响应体不算）。
- 401/403：提示无权限。

## 功能点

| 功能点 | 需求 |
|---|---|
| 告警消息 | [alerts.md](./alerts.md) |
| 告警策略 | [rules.md](./rules.md) |
| 告警策略的创建与编辑 | [alerts-write.md](./alerts-write.md) |

## 明确不做

- 集群级与内置告警策略的编辑（由安装器维护）。
- 告警消息的静默、屏蔽与通知配置。
- 项目作用域当前没有活动告警，只能验证项目消息列表的空态；内置 `globalalerts` 有真实活动告警，用于策略详情的消息历史验收（已实测 2026-11-15）。集群级两页签继续复用同一 `RuleGroupBody`，因此详情消息区在集群页同时生效。

## 假设

- 告警接口在模块启用后返回标准 `items`/`totalItems` 结构。
