# 告警策略列表（L3）

[子模块需求](./_index.md)

## 概述

告警策略表：名称（副行显示作用域）、策略状态、规则数、类型（内置/自定义）、创建时间；行操作「详情」「启用/停用」。

**两种资源模型**：KubeSphere 3.3 及更早用 `alertingrules`；当前 API 组用**规则组**（`globalrulegroups` / `clusterrulegroups` / 命名空间级 `rulegroups`），每组含若干 Prometheus 规则。页面同一张，模型由探测 API 组决定。

项目级自定义策略的创建、编辑与删除是本页的行操作，字段与请求体见 [alerts-write.md](./alerts-write.md)。

行操作「详情」打开独立详情页：属性区说明这是什么策略，**规则**逐条列出每条告警的严重度、持续时间、说明与完整表达式，并按该策略当前触发的告警标出每条规则的状态；**告警消息**区以时间线展示这条策略触发的告警（时间、状态、级别、摘要、监控目标、当前值）。详情页路径 `…/alertingrules/<name>?scope=global|cluster|project`，`scope` 指明规则来自哪个集合。

## 用户故事

### US1 - 看清哪些策略启用、各有多少规则 (Priority: P1)

作为 **项目运维**，我希望 **在列表上看到启用状态与规则数**，以便 **确认监控覆盖是否如预期**。

**Independent Test**：打开告警策略页，核对列与启用徽章。

### US2 - 知道一条策略里具体有哪些告警 (Priority: P1)

作为 **项目运维**，我希望 **点开一条策略就能看到它包含的每一条告警及其严重度、持续时间与表达式**，以便 **判断某类告警是否真的被覆盖，而不是只看规则条数**。

**Independent Test**：打开某规则组详情，核对规则行数与接口返回的 `spec.rules` 长度一致，且每行显示严重度与表达式。

### US3 - 只启用或停用，不改规则体 (Priority: P2)

作为 **集群管理员**，我希望 **只切换策略的启用状态**，以便 **不会因为一次开关操作覆盖掉别人正在编辑的规则内容**。

**Independent Test**：对一条策略点「停用」，然后读取该对象，核对只有 `alerting.kubesphere.io/enable` 标签变化、`spec.rules` 内容不变；再点「启用」还原。

### US5 - 自己建一条策略并改它 (Priority: P1)

作为 **项目管理员**，我希望 **在页面上创建、修改、删除本项目自己的告警策略**，以便 **不必写 YAML 就能为项目加一条阈值告警**。

**Independent Test**：创建一条策略 → 回读对象确认 `spec.rules` 的告警名与表达式 → 编辑表达式 → 回读确认 → 删除 → 回读 404。

### US6 - 点开一条策略，看清每条规则与它当前的告警状态 (Priority: P1)

作为 **项目运维**，我希望 **在策略详情页看到每条规则的名称、严重度、持续时间、说明与完整表达式，并知道哪条规则正在告警**，以便 **判断一条策略到底覆盖了什么、现在哪条在响**。

**Independent Test**：从列表打开一条含规则的策略详情，核对规则表行数等于接口 `spec.rules` 长度、表达式全文可见、状态列取自该策略的活动告警；没有规则时说明而不是空表。

### US7 - 在策略详情里看这条策略的告警消息 (Priority: P1)

作为 **值班运维**，我希望 **在策略详情里按时间倒序看到这条策略触发的告警消息**，以便 **不必切到总告警列表再按策略名筛一遍**。

**Independent Test**：打开一条正在告警的策略详情，核对消息区行数不超过 10、总数与接口 `totalItems` 一致、首行是最新一条；打开一条没有告警的策略，显示明确空态；消息接口失败时显示错误与重试。


### US8 - 一次停用多条策略 (Priority: P2)

作为运维者，当一批策略需要同时停用（例如维护窗口），我可以在列表里多选后一次停用/启用，而不是逐条点行操作；结果要告诉我处理了几条、哪几条失败。
## 验收场景

- **AC-L3-KUBE-FRONTEND-MONITORING-RULES-01** — 已知集群提供规则组资源，当打开告警策略页，则列出全部规则组，列含名称（副行为作用域）、策略状态、规则数、类型、创建时间；每行规则数等于该组 `spec.rules` 长度；页面状态为 `ready`；分页总数等于各来源合并后的条数；可用「策略状态」筛选（已启用/已停用）把合并后的列表收窄，筛选后总数与分页跟随过滤集合。
- **AC-L3-KUBE-FRONTEND-MONITORING-RULES-02** — 已知某规则组处于启用状态，当对它点「停用」，则其 `alerting.kubesphere.io/enable` 标签变为 `false`、状态徽章变为「已停用」，且 `spec.rules` 未被改动；再点「启用」后标签与徽章还原。
- **AC-L3-KUBE-FRONTEND-MONITORING-RULES-03** — 已知某规则组包含若干规则，当打开它的「详情」，则显示所属作用域、状态、类型、规则数，并逐条列出告警名称、严重度、持续时间与说明（含表达式全文）；规则数为 0 时显示「该规则组没有规则」而不是空表格。
- **AC-L3-KUBE-FRONTEND-MONITORING-RULES-04** — 已知选定了某个项目，当创建一条策略（策略名 + 一条或多条规则，每条含告警名、表达式、持续时间、严重度、说明）并提交，则该项目命名空间下出现对应的 `rulegroups` 对象，其 `spec.rules` 与填写内容逐条一致；当通过行操作编辑（增删规则、改表达式）并提交，则回读对象的规则列表已更新；当删除该策略，则对象不再存在。内置或集群级规则组不提供编辑/删除入口。
- **AC-L3-KUBE-FRONTEND-MONITORING-RULES-05** — 已知某规则组含 N 条规则（N 可能为 0），当从列表行操作「详情」打开它，则页面地址落在 `…/alertingrules/<name>` 且带 `scope` 参数、页面状态为 `ready`；属性区显示名称、作用域、策略状态、类型、规则数与创建时间；规则表有 N 行，每行显示告警名称、严重度、持续时间、说明与完整 PromQL 表达式（不截断），并显示「告警中 / 待触发 / 正常」之一作为该规则当前状态（由该策略的活动告警按 `labels.alertname` 推导，不伪造状态）；N 为 0 时显示「该规则组没有规则」而不是空表；点返回入口回到告警策略列表。
- **AC-L3-KUBE-FRONTEND-MONITORING-RULES-09** — 已知某规则组含 N 条规则（N 可能 >10），当打开策略详情，则规则表每页显示 10 条并在表格下方显示「第 x-y 条，共 N 条规则」与上一页/下一页按钮（N ≤ 10 时不渲染分页器）；当在规则搜索框输入关键字（匹配告警名称、PromQL 表达式、摘要、说明或级别，不区分大小写），则规则表只显示匹配行且分页回到第 1 页，无匹配时显示「没有匹配「关键字」的规则」而不是空表；清空关键字后恢复全部规则。
- **AC-L3-KUBE-FRONTEND-MONITORING-RULES-07** — 已知列表里有多条当前身份可写的策略，当勾选其中若干条并点批量「停用」，则逐条把 `alerting.kubesphere.io/enable` 置为 `false`、回读全部变为已停用，页面显示「已处理 N 条」；再批量「启用」后全部还原；没有 update 权限的行不出现复选框（选择即写入，不可写的行不能被选中）；部分失败时提示已处理条数与失败名单，且不回滚已成功的行。
- **AC-L3-KUBE-FRONTEND-MONITORING-RULES-06** — 已知某规则组当前触发 M 条告警（M 可能为 0），当打开它的详情，则「告警消息」区以 `activeAt` 倒序显示最多 10 条消息，每条显示触发时间、状态（告警中/待触发）、级别、摘要、消息正文，并在接口提供时显示监控目标与当前值；区头显示「共 M 条」，M 大于 10 时分页可翻页；M 为 0 时显示「该策略当前没有告警消息」与说明，不显示错误面板；消息接口失败时该区显示错误与重试，重试成功后恢复列表；无权限（403）时显示无权限原因且不提供重试。

## 设计目标

1. 一页覆盖两代资源模型，读者不需要知道集群是 3.3 还是 3.4。
2. 开关只动一个标签，不重发规则体。
3. 规则内容可读：表达式不截断。
4. 策略详情是一个页面而不是弹窗：规则与告警消息各自有加载/空/错误状态，弹窗承载两个独立数据源会变成一个装在对话框里的页面。

## 约束与边界

- 读 `/apis/alerting.kubesphere.io/v2beta1/{globalrulegroups,clusterrulegroups}`；选定项目时追加该项目的 `rulegroups`。
- 写 `alerting.kubesphere.io/enable` 标签（merge patch）。
- 不支持跨命名空间列出规则组：API 没有该集合，「全部项目」只列集群级规则组。
- 内置规则组（`alerting.kubesphere.io/builtin: true`）只读，不提供编辑入口。
- 写项目级自定义策略时走 `POST/PUT/DELETE /apis/alerting.kubesphere.io/v2beta1/namespaces/<ns>/rulegroups`；PUT 携带读到的 `resourceVersion` 并合并既有注解。
- 告警消息读聚合 v2beta1 集合：项目 `GET /kapis/alerting.kubesphere.io/v2beta1/namespaces/<ns>/alerts`、集群 `…/clusteralerts`、内置/全局 `…/globalalerts`；按策略过滤用 `label_filters=rule_group=<name>`（服务端过滤，再分页），排序 `sortBy=activeAt&ascending=false`。
- 详情页的 `scope` 来自列表行数据（global/cluster/project），决定读哪个规则组集合；同名的全局策略与项目策略是两条不同对象。

## UI 交互设计

- 列：名称（副行作用域）、策略状态、规则数、类型、创建时间；窄屏依次折叠。
- 工具栏：项目筛选与「策略状态」筛选（全部/已启用/已停用，前端对已合并的集合过滤；分页与总数跟随过滤结果）。
- 行操作：详情、启用/停用（两个互斥 `visible` 的条目，因为行操作标签是静态的）。
- 列表行操作「详情」导航到详情页（不是弹窗）；弹窗只用于创建/编辑与删除确认。
- 详情页顺序：返回链接 → 标题（名称 + 状态/作用域/类型徽标 + 描述）→ 操作（编辑/启停/删除，按权限与所有权出现）→ 基本信息 → 规则 → 告警消息。
- 规则表列：状态、告警名称、严重度、持续、说明（含消息）、表达式（含阈值，完整换行）。
- 告警消息区：时间线（时间、状态徽标、级别、摘要、消息、监控目标、当前值），区头总数，底部上一页/下一页；空态与错误态在区内呈现。

## 文案与校验

- 状态：已启用 / 已停用。
- 类型：内置 / 自定义。
- 作用域：全局 / 集群 / 项目。
- 空态：暂无告警策略。
- 详情：规则表状态词「告警中 / 待触发 / 正常」；告警消息空态「该策略当前没有告警消息。」与说明「规则触发后会在这里留下记录；没有记录表示该策略当前没有告警。」；分页文案「第 {page} / {pages} 页」。

## 边界情况

- 集群没有该资源：退回 3.3 的 `alertingrules` 实现（同一页面）。
- 规则组无规则：规则数显示 0，详情里说明。
- 项目筛选为「全部项目」：只列集群级规则组，页面说明原因。
- 详情读入的策略对活动告警：规则状态按 `labels.alertname` 匹配；匹配不到视为「正常」；活动告警超过一次读取上限（100 条）时提示只读入了前 N 条，不假装全量。
- 详情读不到对象（404）：错误面板 + 返回列表；403：无权限说明且不提供重试。
- 告警消息接口失败：消息区局部错误 + 重试，详情其余部分保持可用。

## 明确不做

- 内置与集群级规则组的编辑：由安装器维护，改了下一次协调会覆盖。
- 规则的排序与分组：规则列表按录入顺序写入，Prometheus 不区分规则顺序。
- 告警消息删除以外的批量操作；告警消息本身不提供删除（聚合 API 无 item DELETE 路由，见 `alerts.md`）。
- 模板规则（`exprBuilder` / 阈值模板）的构建与展示：本页只读自定义 PromQL；PromQL 规则没有独立阈值字段，阈值就是表达式里的比较。
- 逐策略通知渠道：老 console 告警策略页族的表单没有该字段（通知在平台「通知管理」的独立对象中），规则组 CRD 的 `spec` 只有 `interval` / `partial_response_strategy` / `rules`（2026-11-15 实测 schema），本页不提供。

## 假设

- 规则组返回标准 `{items}` 信封；规则体遵循 Prometheus 规则格式（`alert` / `expr` / `for` / `severity` / `annotations`）。
- 聚合告警集合返回 `{items, totalItems}`，且 `label_filters=rule_group=<name>` 由服务端执行；实测 `globalalerts` 带该过滤时总数从 44 降到 30（2026-11-15）。
- 活动告警只会随评估周期变化；详情页与消息区不要求两次请求之间完全静止，对账以同次读取为准。

## 功能需求

- **FR-L3-KUBE-FRONTEND-MONITORING-RULES-01** — 按 API 组探测资源模型，同一页面支持 `rulegroups` 与 `alertingrules`。
- **FR-L3-KUBE-FRONTEND-MONITORING-RULES-02** — 规则组列表合并多个来源并在前端分页；策略状态筛选作用于合并后的全集，分页总数随过滤集合变化。
- **FR-L3-KUBE-FRONTEND-MONITORING-RULES-03** — 启用/停用只写 enable 标签。
- **FR-L3-KUBE-FRONTEND-MONITORING-RULES-04** — 详情展示每条规则的名称、严重度、持续时间与表达式。
- **FR-L3-KUBE-FRONTEND-MONITORING-RULES-05** — 项目级、非内置的策略可创建、编辑（描述与规则列表）与删除；其余只读。
- **FR-L3-KUBE-FRONTEND-MONITORING-RULES-06** — 编辑器编辑整条规则列表：可增删规则、逐条校验（告警名与表达式必填、同一策略内告警名唯一）。
- **FR-L3-KUBE-FRONTEND-MONITORING-RULES-07** — 详情页按 `scope` 读取单条规则组，展示身份信息与规则逐条（含完整表达式），并由活动告警推导每条规则的状态。
- **FR-L3-KUBE-FRONTEND-MONITORING-RULES-08** — 详情页的告警消息区按 `label_filters=rule_group` 服务端过滤、按 `activeAt` 倒序分页，空态/错误/无权限分别呈现。

## 成功标准

- **SC-L3-KUBE-FRONTEND-MONITORING-RULES-01** — 列表规则数与接口一致；开关后回读标签一致且规则体未变。
- **SC-L3-KUBE-FRONTEND-MONITORING-RULES-02** — 创建、编辑、删除项目级自定义策略后，API 回读分别证明对象存在且字段一致、规则列表更新、对象不存在。
- **SC-L3-KUBE-FRONTEND-MONITORING-RULES-03** — 详情页规则行数与接口 `spec.rules` 一致，表达式全文可见，状态词只为「告警中/待触发/正常」。
- **SC-L3-KUBE-FRONTEND-MONITORING-RULES-04** — 详情页消息区总数与接口过滤后的 `totalItems` 一致，行数不超过一页，倒序，空态/失败/重试可复现。
