# 企业空间控制台的列表刷新（L3）

[子模块需求](./_index.md)

## 概述

企业空间控制台里的三个列表——角色、项目、配额——各自持有自己的查询。读者在别处（另一个标签页、kubectl、或被邀请的成员刚被加入）改变状态后，需要一个明确的重读入口；老 console 的每个列表都有刷新，新 UI 此前没有。

## 用户故事

### US1 - 主动重读当前列表 (Priority: P1)

作为 **企业空间管理员**，我希望 **在角色/项目/配额列表上直接刷新**，以便 **不必关掉页面重进才知道刚刚的变更是否生效**。

**Independent Test**：打开企业空间的项目列表，在别处新建一个项目后点击列表上的「刷新」，新行出现；搜索一个不存在的名称使列表进入空态，空态给出「清空搜索与筛选」与「刷新」两个出口。

## 验收场景

- **AC-L3-KUBE-FRONTEND-ACCESS_CONTROL-WORKSPACE_LISTS-01** — 已知企业空间控制台的角色、项目、配额三个列表均已加载，则每个列表都显示「刷新」按钮且空闲时可用；当点击项目列表的「刷新」，则重新发起该项目集合请求（请求带 `labelSelector` 的命名空间列表）；刷新期间按钮显示忙碌状态并在请求返回后恢复可用；三个列表的刷新句柄分别为 `workspace-roles:refresh`、`workspace-projects:refresh`、`workspace-quota:refresh`。这三个列表没有搜索框，因此其空态只提供「刷新」出口（带搜索的列表另由所属页族的用例覆盖「清空搜索与筛选」）。

## 设计目标

1. 三个列表用同一份实现（`useListRefresh`），句柄与文案一致。
2. 刷新是读者主动触发的重读，不引入定时轮询。

## 约束与边界

- 每个列表只刷新自己的查询；角色与项目互不影响。
- 空态出口由列表组件在存在 `onRefresh`/`onSearchChange` 时渲染，文案来自 `emptyLabels`，与工具栏的刷新同源。

## 明确不做

- 定时轮询与 watch 推送：会改变请求量与页面状态机，登记在能力矩阵 R-27。
- 跨列表的「全部刷新」：三个列表的查询互不依赖，一个按钮刷新三个会掩盖哪个列表变慢。

## UI 交互设计

- 工具栏：搜索框（仅带搜索的列表）、右侧「刷新」按钮；刷新进行中按钮显示旋转图标并禁用，请求返回后恢复。
- 空态：存在 `onRefresh` 时给出「刷新」按钮；存在搜索或筛选时另给「清空搜索与筛选」。

## 文案与校验

- 刷新按钮文案取 `common.refresh`（中文「刷新」/英文 Refresh），空态文案取 `table.clearSearchAndFilters` 与同一份刷新文案。
- 无表单，不做输入校验。

## 边界情况

- 请求失败：列表显示错误面板与重试，刷新按钮仍可用。
- 慢请求：按钮保持忙碌且禁用，避免重复触发同一查询。

## 假设

- 三个页面各自持有独立查询，刷新互不影响。

## 功能需求

- **FR-L3-KUBE-FRONTEND-ACCESS_CONTROL-WORKSPACE_LISTS-01** — 企业空间控制台三个列表的刷新与空态出口。

## 成功标准

- **SC-L3-KUBE-FRONTEND-ACCESS_CONTROL-WORKSPACE_LISTS-01** — 点击刷新后列表反映服务端的最新数据；空态不是死路。
