# 集群显卡（L3）

[子模块需求](./_index.md)

## 概述

集群内的物理显卡，一张卡一行：属于哪个节点、序号、UUID、健康状态、型号、显存（已用 / 总量）与厂商。顶部给出服务端汇总的健康比例；点显卡 ID 进入单卡详情，看该卡的全部只读属性与用量。

健康是**结论，不是计算**：HAMi device plugin 判定每张卡是否健康，gpu-agent 把结论汇总进节点注解 `hami.io/node-gpu-info`，接口只读这份汇总。页面不按 allocatable 差额反推，也不解析厂商专属注解。

## 用户故事

### US1 - 集群运维按节点核对每张卡的健康状态

作为 **集群运维**，我希望 **在集群显卡列表里按节点核对每张卡的状态**，以便 **判断某台机器是否还能继续接收 GPU 任务**。

**Independent Test**：打开 `/clusters/host/gpus`，表格行数等于 `GET /kapis/gpu.kubesphere.io/v1alpha1/gpus` 的 items 数，健康行数等于 `health:true` 的条数，顶部健康比例与 `/gpus/stats` 一致。

### US2 - 点进单卡看到它的详细属性

作为 **集群运维**，我希望 **点一张卡看到它的节点、序号、UUID、型号、厂商、显存与用量**，以便 **在列表只给出状态结论时继续下钻**。

**Independent Test**：从列表点某个显卡 ID 进入 `/clusters/host/gpus/<uuid>`，详情页的显卡 ID 与被点行一致，节点、序号、型号、厂商、显存与状态可读。

## 验收场景

- **AC-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-GPU-01** — 已知集群有 GPU 节点，当打开集群显卡列表，则每张物理卡一行（节点 / 序号 / 显卡 ID / 状态 / 型号 / 显存（已用 / 总量）/ 厂商），行数等于接口 items 数、健康行数等于 `health:true` 的计数，顶部显示服务端汇总的健康比例；点某一行的显卡 ID 进入单卡详情，详情页的显卡 ID 与该行一致，节点 / 序号 / 型号 / 厂商 / 显存 / 健康状态可读；该 UUID 已不存在时显示明确提示而不是空白页。

## 设计目标

1. 一眼看出「哪台机器上的哪张卡不健康」，而不是只看到总数。
2. 列表与单卡详情对同一张卡给出同一个结论（同一份接口数据）。
3. 显存这类带单位的量不产生「183359 是 MB 还是 GB」的歧义。

## 约束与边界

- 数据只来自 `gpu.kubesphere.io/v1alpha1` 的 `gpus` 与 `gpus/stats`；不读节点注解、不连 kube-apiserver（宪法 C1）。
- 列表以**物理卡**为粒度，不以 allocatable 计数为粒度：allocatable 回答「还能分几张」，列表回答「机箱里有几张、各自什么状态」。
- 只读：不提供摘卡、重置、切换模式等写操作。

## UI 交互设计

- 顶部：标题 + 说明 + 健康比例条（健康百分比、`健康 / 总数`、按厂商-型号的计数）。
- 表格：节点（含节点 IP，节点名链接节点详情）、序号、显卡 ID（链接单卡详情）、状态、型号、显存（已用 / 总量）、厂商；窄屏隐藏显存与厂商列。
- 单卡详情：返回链接、显卡 ID 标题 + 健康徽标、基本信息区块、用量区块。
- 状态颜色：健康绿、亚健康黄；颜色只是对接口 `health` 布尔值的映射。

## 文案与校验

- 状态：健康 / 亚健康。
- 健康比例：`健康比例 {percent}%`；汇总：`{healthy} / {total} 张健康`。
- 空态：暂无显卡 —— 没有节点上报 GPU 设备；接入 GPU 节点并运行 HAMi device plugin 后，这里会列出每张卡。
- 单卡不存在：这张显卡不存在（可能已从节点上移除）。
- 健康说明：健康来自 HAMi device plugin 的判定，由 gpu-agent 汇总进节点注解；页面只读结论，不重新判定。

## 边界情况

- 节点没有 GPU：该节点不产生行；整个集群没有 GPU 时显示空态。
- 某张卡被 device plugin 摘出可分配池：卡仍在列表里，状态为「亚健康」（device plugin 只改标记、不删卡），不会少一行。
- 直接访问一个已不存在（或已被摘除上报）的 UUID：详情页显示「这张显卡不存在」，不空白、不报错页。
- 接口失败：错误面板 + 重试，不显示上一次的陈旧数据。
- 显存：接口单位是 MiB，页面换算成 GiB 并带上单位；总量为 0 时显示 `-` 而不是 0。
- 健康比例接口失败：不显示比例条（宁可不显示，也不拿一页数据求和冒充全量）。

## 功能需求

- **FR-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-GPU-01** — 按物理卡列出集群 GPU（节点、序号、UUID、健康、型号、显存、厂商），顶部展示服务端汇总的健康比例。
- **FR-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-GPU-02** — 用 UUID 打开单卡详情；UUID 不存在时给出明确提示。

## 成功标准

- **SC-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-GPU-01** — 列表行数 = 接口 items 数，健康行数 = `health:true` 条数；点行进入详情后 UUID 一致。

## 明确不做

- 批量摘卡 / 批量重置：摘卡是 device plugin 的行为，控制台不提供会与调度器打架的按钮。
- 跨集群聚合：一个集群一个列表，聚合会掩盖「哪台机器」这个问题。
- 前端重新判定健康：判定属于 HAMi，页面只读汇总结论。
- 编辑卡属性、切换 vGPU 模式：模式切换属于「设置 vGPU 模式」页，不在本页。

## 假设

- GPU 节点运行 HAMi device plugin，且 gpu-agent 在写 `hami.io/node-gpu-info`；没有这两者时接口返回空列表，页面显示空态。
