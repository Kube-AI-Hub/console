# 集群概览（L3）

[子模块需求](./_index.md)

## 概述

集群的落地页。用一屏回答三个问题：**这是什么集群**（供应者、Kubernetes 与 Kube AI Hub 版本、连接方式、API 端点、就绪状态）、**它有多忙**（CPU / 内存 / 容器组 / 节点 / GPU 卡的已用与总量，以及控制面的请求速率、延迟与调度结果）、**装了哪些模块**（告警、监控、日志、网关等）。

老 console 的集群首页同样是仪表盘而不是列表，本功能点是它的对位迁移。

## 用户故事

### US1 - 打开集群先看整体是否正常 (Priority: P1)

作为 **集群管理员**，我希望 **进入集群的第一屏就能看到就绪状态、版本、节点数与资源用量**，以便 **不必先点进节点或监控才能判断这个集群能不能用**。

**Independent Test**：打开集群概览，核对「基本信息」与「资源用量」两块都渲染出真实值，且状态徽标与集群对象的 Ready 条件一致。

### US2 - 判断「有没有空间」而不是只看百分比 (Priority: P1)

作为 **集群管理员**，我希望 **已使用、总量、使用率和已分配各自对齐呈现**，以便 **区分「跑得满」和「申请满了但实际很闲」——后者意味着新 Pod 调不进来**。

**Independent Test**：核对 CPU、内存卡分别出现已使用、总量、使用率与已分配字段，且数值与监控接口返回一致；不存在合并斜杠文本的依赖。

### US3 - 知道这个集群装了哪些可选模块 (Priority: P2)

作为 **集群管理员或支持人员**，我希望 **概览列出已启用与未启用的模块**，以便 **在排查页面不可用时确认配置开关，而不把开关误当成 API 安装证明**。

**Independent Test**：核对模块区分为「已启用」与「未启用（N）」两组，条目与集群对象 status.configz 一致。

### US4 - 没有监控后端时页面仍然可用 (Priority: P2)

作为 **集群管理员**，我希望 **监控缺失只影响用量面板并明确说明**，以便 **仍然能看到版本、就绪状态与模块信息**。

**Independent Test**：在监控接口返回失败的环境下打开该页，核对基本信息与模块区正常渲染，用量面板显示「监控数据不可用」而不是 0。

### US5 - 优先定位资源压力并查看变化 (Priority: P1)

作为 **集群运维人员**，我希望 **先看资源总量/用量和节点排行，并切换资源趋势**，以便 **快速定位压力与异常节点**。

**Independent Test**：资源和排行先于身份信息；切换资源与1h/6h/24h，趋势与同次历史响应对账；默认30秒更新，可暂停，隐藏页面不继续轮询。

### US6 - 一次点击进入 kubectl 排障 (Priority: P1)

作为 **集群管理员**，我希望 **在概览点击一次就打开当前账号终端**，以便 **不离开概览或再次点击准备按钮**。

**Independent Test**：页面打开不查询工具目标，按钮点击后原地出现准备/终端；执行只读标记，关闭释放连接，取消准备后晚到响应不重开。

## 验收场景

- **AC-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-OVERVIEW-01** — 已知已登录且对集群有读取权限，当打开集群概览页，则「基本信息」显示状态徽标（就绪时「运行正常」）、供应者、Kubernetes 版本、Kube AI Hub 版本、节点数、连接方式、API 端点与描述；就绪时不重复显示 Ready 条件的说明文字（该说明只在未就绪时出现，且与「未就绪」徽标同行，因为它此时是唯一的下一步线索）；「已启用模块」列出 status.configz 中为真的模块、「未启用」列出为假或缺失的模块，不代表 API 未安装；页面不出现项目工作区栏。
- **AC-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-OVERVIEW-02** — 已知集群存在且监控后端可用，当查看「资源用量」，则 CPU、内存、容器组、节点各显示已使用、总量与使用率，CPU 与内存额外显示已分配；集群有 GPU 时显示 GPU 实际使用、总数和独立已分配量，不再附加 GPU 利用率文本行；当监控接口不可用时，用量面板显示监控不可用说明而不是 0 或空白，基本信息与模块区不受影响。Kubernetes 状态保留请求速率、延迟、scheduled/error/unschedulable 五字段。

- **AC-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-OVERVIEW-05** — 基本信息显示集群可见性；六类系统组件入口按当前集群和分类进入列表，可清除分类，详情保持同集群。kubectl只在主动点击后准备并连接；主动打开kubeconfig时只读当前用户/集群配置，提示并可下载kubeconfig.yaml。关闭取消读取并清除敏感缓存，身份或集群变化不显示旧内容，403不提供重试，不记录或截图凭据正文。

- **AC-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-OVERVIEW-09** — 默认30秒协调资源、选中趋势、排行与Kubernetes状态刷新，可暂停/恢复；隐藏时暂停，可见恢复后刷新一次。有请求未完成不叠加轮询，离开或切集群清理计时器/观察器。暂停/继续与刷新采用简短图标文字次要按钮，图标随运行状态切换，完整自动刷新语义和周期通过可访问名称及提示保留；kubectl为强调主按钮，不显示最近刷新时间。失败明确说明，保留旧值时有旧值标识，手动刷新保留原全部查询范围并显示等待状态。
- **AC-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-OVERVIEW-10** — kubectl按钮一次点击即原地显示近全屏准备弹窗，再解析当前用户/集群工具目标并连接，不需第二次点击。关闭取消准备/释放终端、晚到响应不重开，重开重新读取目标，身份/集群变化关闭旧会话。403无重试，不创建工具Pod；直接访问原kubectl路由仍主动开启，原生键盘/ANSI/PTY/首次输出就绪保留。
- **AC-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-OVERVIEW-11** — 基本信息与 Kubernetes 状态使用同一套行式属性表：每行一条字段，标签在左列（14px、中等字重、主色），值在右列（12px、次色），标签是行里更大的一半；字段之间以 1px 主题分隔线相连且分隔线横跨标签列与值列（两半在同一 y，不出现错位断线）；状态与可见性把说明文字并入值节点，不另起一行标签。两块合计高度在同一视口下比改动前的单列堆叠下降至少 40%，1024/1280/1600 三档下标签不换行、值可换行，两块标签列起点一致且值列起点一致（相邻行偏差小于 2px），标签与值的计算色在深浅两主题下均达到 4.5:1。

- **AC-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-OVERVIEW-13** — 未就绪集群（Ready 条件非 True）的集群侧栏只放行「集群概览」：其余页面项置为禁用——不可点击、不保留 href、`aria-disabled="true"`、悬停说明「未就绪」，并带锁定标记；分组仍可展开，让读者看到有哪些页面，但叶子项不可进入。加载中（集群列表尚未返回）不锁定任何项，避免每次进入集群都闪一下灰菜单。直接访问被禁页面的 URL（书签、粘贴、浏览器后退）时，集群作用域布局显示与等待页同语言的说明——「该集群尚未加入，此页面在集群就绪前不可用」——并提供前往集群概览的链接，不把 apiserver 的 `cluster <id> is not ready` 英文原文抛给读者。集群就绪后侧栏恢复可点击，守卫不再出现。

## 设计目标

1. **运维优先**：先资源容量/用量，再节点排行，最后身份、控制面、组件与模块；首屏直接定位资源压力。
2. **数字要能自证**：任何百分比旁边必须有分子分母；任何单点数字必须能对应到一个具体资源。
3. **降级要说明理由**：缺数据时说明缺什么，不显示 0。

## 约束与边界

- 读集群对象 /kapis/cluster.kubesphere.io/v1alpha1/clusters/<id>。
- 读监控 /kapis/monitoring.kubesphere.io/v1alpha3/cluster 与 /components/{apiserver,scheduler}（KubeSphere 监控 API，不是 metrics.k8s.io）。
- 只读：本页不提供任何写操作。
- 历史复用rangeMetricsApi与现有monitoring接口，不新增后端指标，不直连Prometheus。

## UI 交互设计

- 顶部集群名、低强调度的图标文字暂停/继续及刷新按钮、强调主操作kubectl，不显示最近刷新时间；六资源/趋势优先，下一行节点统计及排行约1:2，节点不显示历史趋势。辅助行沿用同列宽，使基本信息/Kubernetes状态对齐节点数block；窄屏纵向排列，代理提示保留。
- 节点块与排行共用同一行高：两块头部等高（排行带指标下拉，节点块放「查看全部节点」文字链接），正文把环图与就绪/总量数字作为一组在槽内垂直居中，不留中间空白。
- 基本信息与 Kubernetes 状态采用行式属性表：左标签列固定上限、右值列占余量，字段间 1px 分隔线贯穿两列；标签用更大字号（14px 中等字重）与主色，值用 12px 次色，扫读时先按字段名定位再读值。状态徽标与就绪消息、可见性短标签与说明都放在值节点内。
- 常用运维入口四项复用同款共享按钮，链接保留导航语义；固定相同高度与内边距、两列等宽、图标及文字左对齐。
- 资源卡统一名称、已使用/总量双列、使用率与进度条、分配量固定区域；不支持的分配字段留空，无额外 GPU 利用率文本行。
- 环图与百分比同源，中心为图标，数字与单位独立可读；趋势和选中态可键盘使用，颜色不替代文本。
- 模块以徽标（已启用）与弱化文字（未启用）两种形态出现；原始键名放 title，悬停可见。
- 资源卡与选中趋势后为Top5，再为全部辅助面板；完整排行仍共享读模型。配置开关不替代组件入口；暂停自动更新不关闭手动刷新或终端。

## 文案与校验

- 状态：就绪且启用 →「运行正常」；未就绪 →「未就绪」；spec.enable 为 false →「已停用」。Ready 条件的 message 只在未就绪（含已停用）时显示在徽标右侧，就绪时省略——那时它只是重复徽标，而集群列表页也遵循同一规则。
- 平台版本字段标签为「Kube AI Hub 版本」（英文「Kube AI Hub version」），locale key 为 `cluster.overview.productVersion`，数值仍读 `status.kubeSphereVersion`。
- 缺值统一 -。
- 延迟在 1 秒以下按毫秒显示（14.85 ms），1 秒以上按秒。
- 「无法调度」仅在非零时用警示色强调。

## 边界情况

- 监控后端缺失：用量面板显示「监控数据不可用」加一句说明，页面其余部分照常。
- 集群无 GPU：不渲染 GPU 行（0 / 0 读起来像功能坏了，而 CPU-only 集群是正常形态）。
- 未知模块键：原样显示键名（configz 是开放的，任何插件都可能新增），不丢弃。
- 集群对象读取失败：显示错误面板与重试。
- 集群 Ready 条件缺失：按未就绪处理，不默认健康。

## 功能需求

- **FR-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-OVERVIEW-01** — 基本信息来自集群对象，就绪状态只认 Ready 条件的 True。
- **FR-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-OVERVIEW-02** — 用量与 Kubernetes 状态来自 KubeSphere 监控 API，一次请求取多个指标。
- **FR-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-OVERVIEW-03** — 监控不可用时页面降级而非整体失败。
- **FR-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-OVERVIEW-04** — 模块列表区分已启用与未启用，未知键原样显示。

## 成功标准

- **SC-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-OVERVIEW-01** — 基本信息、用量、模块三区的值与同名接口返回一致；监控不可用时页面仍可读。

## 明确不做

- 集群设置（编辑描述、可见性、可插拔组件开关）：需平台侧写接口，当前迁移范围外。
- 无后端来源的Token、模型数、功率和温度大屏指标；不通过随机动画模拟实时采样。原不画历史的决定被资源趋势需求覆盖。
- 不提供 kubeconfig 编辑或更新成员集群连接配置；只读用户配置与连接配置不是同一任务。原“不提供下载”判断已在 2026-11-15 复盘后反转。
- 不重复节点属性列表；原“节点页承担 Top5”判断缺乏等价证明，现恢复概览预览与完整排行下钻。

## 假设

- 集群对象的 status.configz 以「模块名 → 布尔」的形式给出配置启用状态，不证明 API 安装状态。
- 监控 API 在未安装监控时返回错误而非空结果；两种情形都按「不可用」处理。
