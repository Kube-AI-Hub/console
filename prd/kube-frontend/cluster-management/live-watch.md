# 列表实时刷新（L3）

[子模块需求](./_index.md)

## 概述

集群级容器组列表增加「实时」开关：打开后通过 Kubernetes 的 **watch 流**（`?watch=true` 的分块 HTTP，不是 WebSocket）感知增删改，并让列表查询失效重取。

老 console 的列表靠推送刷新；新 UI 此前只有手动刷新。这里不做逐条重建行——列表自身的排序、分页、字段映射仍只有一份实现。

## 用户故事

### US1 - 排障时看到实时变化 (Priority: P2)

作为 **运维**，我希望 **容器组列表能自动更新**，以便 **在删除/重建容器组时不必反复点刷新**。

**Independent Test**：打开容器组列表并开启实时，状态显示「实时更新中」；关闭后状态消失。

## 验收场景

- **AC-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-LIVE_WATCH-01** — 已知可访问集群 watch 接口，当在容器组列表打开「实时」开关，则开关进入按下状态、状态文本在长连接建立后变为「实时更新中」，且实时开启期间列表仍可正常翻页/改档位；关闭开关后状态文本消失。

## 设计目标

1. 默认关闭：长连接是按需能力，不是默认代价。
2. 断线自动重连，失败退避，不形成热循环。

## 约束与边界

- 只接集群级容器组列表一处；其它列表复用同一 hook。
- 不做事件增量合并。

## UI 交互设计

- 列表上方一个「实时」按钮（aria-pressed 表示状态）+ 状态文本：正在连接 / 实时更新中 / 实时连接失败。

## 文案与校验

- 实时、实时已关闭、正在连接…、实时更新中、实时连接失败，稍后重试。

## 边界情况

- watch 接口 403/不可用：显示失败并退避重试，列表仍可手动刷新。
- 页面切走：abort 连接。

## 明确不做

- 事件增量合并进当前页（与分页/排序冲突）。
- 其它列表默认开启。

## 假设

- BFF 与开发代理都能透传长连接并正确取消。

## 功能需求

- **FR-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-LIVE_WATCH-01** — 提供 watch 客户端与失效重取 hook，并接到容器组列表。

## 成功标准

- **SC-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-LIVE_WATCH-01** — 开启后状态可达「实时更新中」，期间列表操作正常，关闭即中止。

## 验收用例

- `TC-L3-KUBE-FRONTEND-CLUSTER_MANAGEMENT-LIVE_WATCH-01`
