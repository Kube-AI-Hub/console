# 帮助与文档入口（L2）

## 概述

新前端顶栏的**帮助菜单**：两个入口——用户指南与 API 文档——指向部署可配置的文档地址，在当前语言下打开，新窗口打开。旧 console 在登录后的顶栏右侧有一个 documentation 图标下拉，内容来自其 Node 服务端配置 `client.documents[lang]`；新前端的 BFF 就是那个服务端，因此由 BFF 提供同一份配置。

## 用户故事

### US1 - 从控制台直接找到对应语言的文档

作为 **平台用户**，我希望 **在顶栏点开帮助菜单，选择用户指南或 API 文档**，以便 **不记得文档域名或路径时也能一步到达，并保持当前语言**。

**Independent Test**：登录后顶栏出现帮助图标；点开显示「用户指南 / API 文档」两项；点击任一项在新窗口打开对应语言的文档地址；切换语言后再打开，链接跟随语言变化。

### US2 - 部署方决定文档地址，未提供时不出现死链

作为 **部署/运维人员**，我希望 **通过部署配置指定文档地址；如果这个部署没有文档，入口就不显示**，以便 **不需要改前端代码，也不会把用户带到 404**。

**Independent Test**：BFF 环境变量配置文档地址后，菜单使用该地址；显式置空时帮助下图标不渲染；配置接口失败时使用旧 console 的相对路径兜底，菜单仍可用。

## 验收场景

- **AC-L2-KUBE-FRONTEND-HELP-01** — Given 已登录且部署提供两种语言的文档地址，When 查看顶栏，Then 出现帮助图标（可访问名称为「帮助与文档」）；点开后有两项「用户指南 / API 文档」，分别对应当前语言（中文 → `documents.zh`，英文 → `documents.en`）的 URL；点击后在新窗口打开该 URL，且 opener 关系被切断（`noopener`）。
- **AC-L2-KUBE-FRONTEND-HELP-02** — Given 部署通过 BFF 环境变量覆盖文档地址，When 打开帮助菜单，Then 使用覆盖后的地址；Given `GET /api/config` 读取失败，Then 使用旧 console 的内置相对路径（`/kube-docs/...`）而不是隐藏菜单；Given 某项地址被显式置空，Then 该项不渲染（不产生死链），两项都空时帮助图标整体不渲染。
- **AC-L2-KUBE-FRONTEND-HELP-03** — Given 读者在中文与英文之间切换，When 再次打开帮助菜单，Then 链接随语言切换（同一菜单不缓存上一种语言的地址）；菜单不触发整页跳转。

## 设计目标

- 部署配置与代码分离：地址来自 BFF 的 `GET /api/config`，SPA 不硬编码部署域名。
- 「未配置」与「显式为空」分开：未设置 → 内置默认（旧 console 相对路径）；显式空 → 隐藏入口。
- 与顶栏其他控件同一视觉与触控规格；不因读配置阻塞或抖动顶栏。

## 约束与边界

- 只登录后显示（帮助菜单在 AppShell 顶栏，登录页不渲染）。
- 新窗口 + `noopener`：文档站不能反向操作控制台窗口。
- 语言仅 `zh` / `en`；其他语言回落英文（与前端 locale 能力一致）。
- 配置接口未返回前不渲染图标（避免先隐藏再出现的布局跳动）；读失败后按兜底渲染，不把失败当「未配置」。

## UI 交互设计

| 项 | 值 |
|---|---|
| 位置 | 顶栏右侧、语言切换之前（与旧 console 的 documentation 下拉位置一致） |
| 图标 | `documentation` |
| 可访问名 | 「帮助与文档」/「Help and documentation」 |
| 菜单项 | 用户指南（documentation 图标）、API 文档（api 图标） |
| 行为 | 新窗口打开对应语言 URL；菜单不改变当前页面 |
| 触控 | 与相邻顶栏按钮同高（手机上不小于 44px） |
| 句柄 | `shell:help-menu`、`shell:docs-guide`、`shell:docs-api` |

## 文案与校验

- 标题：`shell.help`；两项：`shell.userGuide`、`shell.apiDocs`。
- URL 不做前端校验：部署方配置错误由打开后的文档站返回；前端只负责不渲染空值。

## 边界情况

- 只配置一种语言：另一种语言的两项都为空 → 该语言下整体隐藏（不渲染半截菜单）。
- 配置接口 401/500/超时：使用内置相对路径兜底，并在控制台记录一次失败；不阻塞顶栏。
- 文档 URL 为相对路径：以控制台同源打开（旧 console 就是这样）；绝对 URL 原样打开。
- 同时切换语言与打开菜单：菜单在下一次渲染即用新语言，不缓存旧 URL。

## 明确不做

- 控制台内嵌文档阅读器、文档搜索、上下文帮助（页面级 `pageTip` 已有独立机制）。
- 反馈 / Slack / GitHub 入口：旧 console 的文档下拉只有用户指南与 API 文档两项，不做扩展。
- 每个用户自定义文档地址。

## 功能需求

- **FR-L2-KUBE-FRONTEND-HELP-01** — 顶栏必须提供帮助菜单，包含用户指南与 API 文档，按当前语言选择地址。
- **FR-L2-KUBE-FRONTEND-HELP-02** — 文档地址必须可由部署配置（BFF 环境变量）覆盖，并有内置兜底；显式空值必须隐藏对应入口。

## 成功标准

- **SC-L2-KUBE-FRONTEND-HELP-01** — 配置地址后菜单 URL 与配置一致；未配置走内置路径；显式空值无入口；点击新窗口打开且 `noopener` 生效。

## 假设

- 文档站与控制台同源部署（旧配置使用相对路径）；跨域部署由 `noopener` 直接支持。
- 帮助菜单不要求后端鉴权：`/api/config` 只含公开文档地址。
