# 工作负载 / Pod 详情 · 监控（L3）

[子模块需求](./_index.md)

## 概述

在详情页签体系里新增「监控」页签：CPU 与内存用量随时间（1 小时 / 6 小时 / 24 小时）。数据来自集群监控 API 的区间查询——工作负载读**服务端已按关联容器组求和的** `workload_cpu_usage` / `workload_memory_usage_wo_cache`，Pod 读自身的 `pod_cpu_usage` / `pod_memory_usage_wo_cache`。

页面必须区分三种状态：**监控不可用**（接口报错，通常是集群没有监控后端）、**窗口内无数据**（接口成功但没有采样点）、**用量为 0**（有采样点且值为 0，正常画图）。把 0 当缺失、或把空结果当报错，都会把读者引向错误的排查方向。

## 用户故事

### US1 - 在工作负载详情里判断它最近的资源用量

作为 **项目成员**，我希望 **在 Deployment / Pod 详情里直接看 CPU 与内存随时间的变化**，以便 **判断扩容、重启或流量变化前后的资源占用，而不用跳到集群监控再手动筛出这个负载**。

**Independent Test**：打开一个运行中的 Deployment 详情，点「监控」页签：有采样点时出现 CPU 与内存两张趋势图（柱数 > 0）；切到 6 小时窗口后窗口标记随之变化；没有监控后端时显示「监控不可用」而不是空白。

## 验收场景

- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL_MONITOR-01** — 已知 Deployment 有运行中的关联容器组且集群监控在采集，当打开该 Deployment 详情并点「监控」页签，则默认 1 小时窗口显示 CPU 与内存两张趋势（有采样点时图表出现且点数 / 柱数 > 0，值为 0 时画零高度柱而不是空态），可切换到 6 小时 / 24 小时且当前窗口标记与请求区间、采样步长同步变化；当监控接口报错时显示「监控不可用」并可重试，当接口成功但窗口内没有采样点时显示「没有监控数据」，两者不混用；Pod 详情同样有监控页签并读 Pod 自身序列。

## 设计目标

1. 详情页内完成「看这个负载的用量趋势」，不跳页。
2. 三态（不可用 / 无数据 / 0 值）一眼可分。
3. 工作负载趋势与服务端汇总口径一致（同一份 recording rule）。

## 约束与边界

- 数据只来自监控 API 的区间查询（宪法 C1）；页面不直连 Prometheus。
- 工作负载用量是服务端 recording rule 的结果（已按关联 Pod 求和）；**前端不再逐 Pod 相加**，否则会和服务端口径不一致。
- 只在 `deployments` / `statefulsets` / `daemonsets` 与 `pods` 上显示「监控」页签；jobs/cronjobs 没有工作负载级指标，不显示页签（不放会报错的死页签）。
- 窗口三档：1h（60s 步长）、6h（5m）、24h（15m）。
- 不引入图表库：两条 60–100 点的序列用内联 SVG 柱图足够。

## UI 交互设计

- 页签顺序：概览 / **监控** / 关联容器组（Pod 为「容器」）/ 修订版本 / 事件 / 元数据。
- 监控面板：左说明（工作负载「按关联容器组汇总」；Pod「自身用量」）+ 右三档窗口按钮（当前档按 `aria-pressed`）。
- 内容依次可能为：加载骨架 → 「监控不可用」+ 重试 → 「没有监控数据」空态 → 两张趋势卡（CPU、内存）。
- 每张卡：标题 + 当前值；柱状图（每个采样一根柱）；下方最小 / 最大 / 当前。窄屏单列，宽屏两列。
- 机器可读标识：`workload-detail:tab:monitor`、`workload-detail:monitor`、`:range`、`:range:<1h|6h|24h>`、`:chart`（带 `data-ai-window` 与 `data-ai-points`）、`:empty`、`:unavailable`、`:retry`、`:cpu` / `:memory`，柱子 `data-ai-bar`。

## 文案与校验

- 窗口：最近 1 小时 / 最近 6 小时 / 最近 24 小时。
- 指标：CPU 用量 / 内存用量；单位：核、GiB。
- 汇总说明：工作负载「CPU 与内存按该工作负载的关联容器组汇总；数据来自集群监控。」Pod「CPU 与内存是该容器组自身的用量；数据来自集群监控。」
- 空态：该时间范围内没有监控数据。+ 提示（可能刚创建、尚未采集，或指标在此集群不可用）。
- 不可用：监控不可用。+ 提示（确认集群已安装监控组件后重试）+ 重试按钮。
- 数值：CPU 保留三位小数（核），内存换算 GiB 保留两位。

## 边界情况

- 集群没有监控后端 / 接口报错：显示「监控不可用」，不显示空态。
- 对象刚创建、监控尚未采集：接口成功但 0 个采样点 → 空态。
- 有采样点但值全为 0：正常画零高度柱并显示 0，不退化为空态。
- 工作负载没有关联容器组：通常没有序列 → 空态。
- 窗口切换后请求失败：显示不可用，不保留上一个窗口的图。
- 窗口在选定瞬间折算成绝对区间，避免每次渲染都移动窗口。
- 只实现部署/有状态副本集/守护进程集与 Pod；Job/CronJob 无指标，因此没有页签。

## 功能需求

- **FR-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL_MONITOR-01** — 详情页提供「监控」页签，按三档窗口读取工作负载（服务端按 Pod 汇总）或 Pod 自身的 CPU / 内存区间指标并绘成趋势。
- **FR-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL_MONITOR-02** — 区分监控不可用、窗口内无数据与值为 0 三种情况。

## 成功标准

- **SC-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL_MONITOR-01** — 监控页签可达；有采样点时图表出现且柱数 > 0；切换到 6h 后窗口标记变化；不可用与空态各有明确文案。

## 明确不做

- Job / CronJob 的监控页签：监控 API 没有这两类的工作负载级指标。
- 容器级监控（`pod_cpu_usage` 已按 Pod 聚合）：容器粒度属于单容器页面或集群监控。
- GPU 指标：已有「GPU 资源监控」页。
- 告警规则、导出、图表缩放：需要图表库或另一套模块。

## 假设

- 集群启用了监控后端；Deployment / StatefulSet / DaemonSet 的 `namespace:workload_*_usage:sum` recording rule 存在；不满足时页面显示空态或不可用，不报错崩页。
