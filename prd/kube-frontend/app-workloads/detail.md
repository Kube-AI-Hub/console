## 验收场景

- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-JOB_RUNS-01** — 已知一个任务启动过容器组，当打开其详情，则显示「执行记录」表（序号、容器组名称、状态、退出码、开始时间、结束时间），序号从 1 起按创建时间递增。

- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-STATEFUL_SERVICE-01** — 已知一个有状态副本集的 `spec.serviceName` 指向一个存在的 headless 服务，当打开其详情，则显示「关联服务」区块，含服务名称、类型（Headless）、虚拟 IP（None）与端口；当 `serviceName` 指向不存在的服务，则该区块显示显式的错误提示而不是空白。

- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-SERVICE_PODS-01** — 已知一个服务选中了某些容器组，当打开其详情，则同时显示「端口」与「关联容器组」两个区块，且容器组行数等于该服务 `spec.selector` 匹配到的 Pod 数。

- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-PODS_BLOCK-01** — 已知一个部署有就绪的容器组，当打开其详情，则显示「关联容器组」表（容器组名称、状态、所在节点、重启次数、创建时间），行数与该部署选择器匹配到的 Pod 数一致；当点击其中的容器组名称，则跳转到该容器组的详情页。

- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL-05** — 已知一个 ClusterIP 服务有端口 80→8080，当打开其详情，则显示端口表，列为端口名、服务端口、容器端口、节点端口，且服务端口为 80、容器端口为 8080、节点端口为 `-`。

- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL-04** — 已知一个部署配置了自动伸缩（1–3 副本、CPU 30%），当打开其详情，则显示自动伸缩区块含策略名、副本范围与触发指标；已知另一个部署没有自动伸缩，则其详情不显示该区块。

- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL-03** — 已知打开一个容器组的详情，则属性含状态、所在节点、容器组 IP、节点 IP、QoS 等级与重启次数；已知打开一个服务的详情，则属性含服务类型、虚拟 IP、外部地址、选择器与会话亲和性。

- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL-06** — 已知容器组的容器分别声明了资源请求与限制，当打开容器组详情概览，则显示「资源请求」「资源限制」两行，值为该容器组全部容器（含 init 容器）的聚合，每个资源一项；完全没有资源声明时两行显示「-」。
- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL-01** — 已知列表里有一个部署，当点击名称，则进入 `…/deployments/<name>` 并显示属性与容器镜像。
- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL-02** — 已知在详情页，当点返回链接，则回到同一项目的列表，页签仍高亮。

## 设计目标

落实「区域内切换保持上下文」：详情与列表属于同一功能区，页签与工作区栏不重建。

## 约束与边界

- 详情读 kapis 单个对象，属性来自对象本身。
- 「副本」只在有副本概念的资源上显示。
- 容器组的资源请求/限制是**全部容器（含 init 容器）的聚合**：同一资源跨容器相加，不是取第一个容器、也不是取最大值。聚合在客户端完成——kapis 返回的容器组对象里没有现成的合计字段。
- 聚合的每个资源一项（cpu / memory / 扩展资源各一行），按资源名去重；GPU 这类带前缀的资源名简化为最后一段（`nvidia.com/gpu` → `gpu`），否则一行读不下。

## UI 交互设计

标题与状态徽章在上，操作在右，属性块与镜像块在下。

容器组概览的属性块里，「资源请求」「资源限制」各占一行，值里每个资源一项（`cpu 1.5`、`memory 384Mi`），资源之间用分隔符连排；没有任何资源声明时整行显示 `-`，不显示 `0`——「没声明」与「声明为 0」是两件事。

## 文案与校验

- 属性名：集群、项目、应用、副本、创建时间、创建者；容器组另有状态、所在节点、容器组 IP、节点 IP、QoS 等级、重启次数、资源请求、资源限制。
- 资源行标签：「资源请求」「资源限制」；值为空时 `-`。
- 单位：cpu 用核（保留最多三位小数），内存用 Mi，扩展资源用个数。

## 边界情况

- 对象不存在：提示并给返回列表入口。
- 加载中显示骨架。
- 只有部分容器声明了资源：聚合只算声明了的容器，未声明的容器不按 0 参与（也不因此把整行变成 `-`）。
- 资源写法不是标准 quantity（例如带未知单位）：保留原文显示，不当成 0。
- 完全没有资源声明（含 init 容器）：两行都是 `-`。

## 明确不做

- 不在详情做扩缩容（表单能力未迁移，记在待办）。
- 不做「按容器展开的资源明细表」：容器级资源在容器详情页看，概览只回答「这个容器组总共要多少」。

## 假设

- 对象名即路由参数，不额外请求列表。

## 页签体系

详情页已按页签组织：概览 / 关联容器组 / 修订版本（仅部署）/ 事件 / 元数据，容器组详情为 概览 / 容器 / 事件 / 元数据。页签只做视觉分层，数据在页面顶层取一次，切换页签不重新加载。

页签清单、默认页签、隐藏规则与验收场景见 [详情页页签](./detail-tabs.md)，本节只做概述。

## 功能需求

- **FR-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL-03** — 详情按资源类型补充专属属性，与老 console 的字段一致。
- **FR-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL-04** — 有自动伸缩的负载显示其策略，没有的不显示。
- **FR-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL-05** — 服务详情显示端口表，无节点端口的显示 `-`。
- **FR-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL-06** — 部署/有状态副本集/守护进程集详情列出关联容器组。

- **FR-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL-07** — 容器组概览显示「资源请求」「资源限制」两行，值为全部容器（含 init 容器）的聚合，每资源一项，无声明时显示 `-`。

- **FR-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL-01** — 展示属性与容器镜像。
- **FR-L3-KUBE-FRONTEND-APP_WORKLOADS-DETAIL-02** — 提供重新部署、编辑 YAML、删除。
