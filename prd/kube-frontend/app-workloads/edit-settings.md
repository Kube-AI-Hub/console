# 编辑设置（L3）

[子模块需求](./_index.md)

## 概述

部署、有状态副本集、守护进程集和定时任务的详情提供「编辑设置」。能改的项与创建向导里对应的步骤一致。任务只改 Kubernetes 允许更新的策略数字和对象自身的标签、注解。容器组不提供这套表单。

## 用户故事

### US1 - 在部署详情里改节点选择 (Priority: P1)

作为 **项目运维**，我希望 **在已有部署的「编辑设置」里改选择节点**，以便 **不必改 YAML 就能把 Pod 调度到指定节点**。

**Independent Test**：打开一个部署的详情，点「编辑设置」再点「高级设置」，能看到「选择节点」。

### US2 - 任务编辑不包含不可改的 Pod 模板 (Priority: P1)

作为 **项目运维**，我希望 **任务的「编辑设置」只出现可更新的策略**，以便 **不会提交一个会被集群拒绝的节点或容器修改**。

**Independent Test**：打开一个任务的详情，点「编辑设置」，能看到最大重试次数，看不到「选择节点」。容器组详情没有「编辑设置」。

## 验收场景

- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-EDIT_SETTINGS-01** — 已知一个部署已存在，当打开其详情并进入「编辑设置」的「高级设置」，则出现「选择节点」。
- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-EDIT_SETTINGS-02** — 已知一个任务已存在，当打开其「编辑设置」，则出现「最大重试次数」，且不出现「选择节点」。已知打开一个容器组详情，则操作里没有「编辑设置」。
- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-EDIT_SETTINGS-03** — 已知一个部署的容器没有设置资源限额，当在「编辑设置」里为容器填写 CPU/内存的请求与上限并保存，则回读该部署的 `spec.template.spec.containers[].resources` 中 requests/limits 与填写一致；只填请求不填上限时只写 requests；全部留空时 `resources` 字段被移除；请求大于上限或数量写法不合法（例如 `abc`）时在本地拒绝并说明原因，不发请求。
- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-EDIT_SETTINGS-04** — 已知一个部署（有状态副本集/守护进程集同理），当在「编辑设置」里把更新策略改为「同时更新」（有状态副本集/守护进程集为「手动更新」）并保存，则回读 `spec.strategy.type`（有状态副本集与守护进程集为 `spec.updateStrategy.type`）为该值且 `rollingUpdate` 字段被移除；改回「滚动更新」并填写最大不可用/最大超出（有状态副本集为分区）后保存，则回读 `rollingUpdate` 与填写一致；百分比或整数以外的值在本地拒绝。
- **AC-L3-KUBE-FRONTEND-APP_WORKLOADS-EDIT_SETTINGS-05** — 已知一个部署已存在且其选择器为 `app=<name>`，当在「编辑设置」的高级设置里新增节点选择（`kubernetes.io/os=linux`）与容器组注解（`prometheus.io/scrape=true`）并保存，则回读 `spec.template.spec.nodeSelector` 与 `spec.template.metadata.annotations` 与填写一致；当移除容器组标签中「选择器依赖的标签」时，页面给出说明并禁用保存且不发请求；把选择器依赖的标签保留、另加一条新标签后保存，则回读的容器组标签同时包含两者；节点选择留空时该字段被移除。

## 设计目标

落实应用负载「写操作走正确的 API 组」：编辑框只收集创建向导里已有、且该资源创建后仍允许更新的字段。

## 约束与边界

- 部署与有状态副本集可改：更新策略、容器、存储、调度规则、优雅终止、容器组安全上下文、容器组注解、选择节点、工作负载标签与注解、IP 池（仅集群启用 IP 池时）。
- 守护进程集与上相同，但创建向导不提供选择节点，编辑也不提供。
- 定时任务可改创建向导里除名称以外的策略、容器、存储和高级设置，字段落在 `spec.jobTemplate`。
- 任务可改最大重试次数、并行数、完成数、最大运行时间和任务对象的标签、注解。不可改 `spec.template`。
- 容器组规格创建后不可改，不提供「编辑设置」。
- 名称不可改。别名和描述仍走「编辑信息」。部署与有状态副本集的副本数仍走资源状态页的扩缩容。

## UI 交互设计

详情侧栏「更多」里的「编辑设置」打开分页弹窗。改过的页出现保存条，点弹窗确定后提交。已有节点选择时，「选择节点」分组默认勾选。

## 文案与校验

- 形态：分页弹窗，复用创建向导已有文案，不新增 i18n key。

| key | 中文 | 英文 | 用途 |
| --- | --- | --- | --- |
| `EDIT_SETTINGS` | 编辑设置 | Edit Settings | 详情操作 |
| `ADVANCED_SETTINGS` | 高级设置 | Advanced Settings | 编辑弹窗页签 |
| `SELECT_NODES` | 选择节点 | Select Nodes | 高级设置分组 |
| `MAXIMUM_RETRIES` | 最大重试次数 | Maximum Retries | 任务策略 |

- 空的节点选择表示不限制节点。重试次数、并行数、完成数、超时为不小于 0 的整数。

## 边界情况

- 集群未启用 IP 池时，高级设置不显示容器组 IP 池。
- 保存被 API 拒绝时，弹窗保持打开并显示错误。
- 容器组详情不出现「编辑设置」。

## 功能需求

- **FR-L3-KUBE-FRONTEND-APP_WORKLOADS-EDIT_SETTINGS-01**：系统必须在部署、有状态副本集、守护进程集和定时任务的详情提供「编辑设置」，且部署与有状态副本集包含「选择节点」。
- **FR-L3-KUBE-FRONTEND-APP_WORKLOADS-EDIT_SETTINGS-02**：系统必须让任务的「编辑设置」只包含可更新策略和对象级标签、注解，且容器组详情不提供该入口。

## 成功标准

- **SC-L3-KUBE-FRONTEND-APP_WORKLOADS-EDIT_SETTINGS-01**：部署编辑弹窗的「高级设置」页可见「选择节点」。
- **SC-L3-KUBE-FRONTEND-APP_WORKLOADS-EDIT_SETTINGS-02**：任务编辑弹窗可见「最大重试次数」、不可见「选择节点」；容器组详情操作中没有「编辑设置」。

## 明确不做

- 不给容器组做与创建相同的编辑表单。
- 不在任务编辑里提供节点选择、容器或存储。
- 不把名称、别名、描述或副本数扩缩容搬进「编辑设置」。
- 不改服务和应用路由已有的编辑入口。

## 假设

- 操作者已登录，且对目标项目有编辑权限。
- 线上页面在包含本次改动的 console 构建发布后才出现新页签。
