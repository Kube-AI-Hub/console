# 资源详情页（L2）

[上级模块](../_index.md)

## 概述

所有「按名字打开一个对象」的页面共用的骨架：左侧是对象摘要（名称、状态、属性、操作），右侧是页签（资源状态、调度信息、元数据、监控、事件……），页签内容由各资源的子路由决定。

这一层负责的是骨架层面的三件事：**加载时显示什么**、**对象不存在时显示什么并去哪**、**存在时页签怎么切换**。它不负责某个具体资源的字段渲染。

## 用户故事

### US1 - 作为集群运维，打开一条存在的记录，能在页签之间切换并看到各自内容

作为 **集群运维**，我希望 **从列表点进一条记录后能在资源状态、元数据、事件等页签之间切换**，以便 **在一页里看全这个对象的运行情况**。

**Independent Test**：打开一个真实 Pod 的 `/resource-status`，切到 `/metadata` 再切到 `/events`，地址栏与主区同步变化；左侧名称与状态始终可见。

### US2 - 作为集群运维，打开一条已删除的记录，3 秒内回到列表

作为 **集群运维**，我希望 **失效的详情链接不会把我留在空转页面**，以便 **马上回到列表重新找目标**。

**Independent Test**：打开 `/clusters/default/projects/agent-platform/pods/not-exist/resource-status`，地址栏在 3 秒内变为 `/clusters/default/projects/agent-platform/pods`，右上角提示为中文。

## 验收场景

- **AC-FULL-CONSOLE-CORE-RESOURCE_DETAIL-01** — Given 已登录且目标对象存在，When 依次切换该详情页的全部页签，Then 每次切换地址栏与主区同步变化，左侧摘要始终可见，页面不出现未翻译 key。
- **AC-FULL-CONSOLE-CORE-RESOURCE_DETAIL-02** — Given 已登录，When 用不存在的资源名打开同一详情页，Then 页面结束加载、给出中文提示并回退到该页自己的列表入口。

## 设计目标

- 详情页骨架对「不存在」的处理必须是**一处实现、所有资源共用**，否则每加一个资源类型就漏一次。
- 回退目标取页面自己声明的列表入口，而不是从地址栏猜，保证列表的集群 / 命名空间上下文不丢。
- 骨架不感知具体资源类型：它只读 store 的公共状态与页面的 `breadcrumbs`。

## 约束与边界

- 骨架只处理详情请求本身的 404；页签内部的子请求（监控、事件、日志）失败不触发回退，避免「监控没数据就被踢回列表」。
- 页签路由由各资源自己的 `routes.js` 提供，骨架只负责渲染。
- 骨架不改请求层：404 的判定依赖 `src/utils/request.js` 产出的错误对象。

## UI 交互设计

- 左侧摘要：图标、名称、描述、属性列表、操作按钮组；顶部一行「返回列表」面包屑。
- 右侧：页签导航 + 主区；页签为链接，切换不刷新整页。
- 不存在时：先结束加载，再发提示，再 `replace` 到列表；三者顺序固定，避免提示还没渲染就被卸载。

## 页面结构

```text
DetailPage（骨架）
├── BaseInfo（左栏）
│   ├── 面包屑（返回列表）
│   ├── 名称 / 描述 / 状态
│   ├── 属性列表
│   └── 操作按钮组
└── 页签导航 + renderRoutes(routes)
```

## 异常态

| 异常 | 用户看到 | 停在哪 |
| --- | --- | --- |
| 加载中 | 页面级 Loading | 当前详情路由 |
| 404 不存在 | 右上角中文提示 + 页面切换 | 该详情页的列表入口 |
| 403 无权限 | 既有行为：跳登录页 | 登录页 |
| 500 / 网络错误 | 既有行为：错误提示 | 当前详情路由（不新增回退） |

## 功能需求

- **FR-FULL-CONSOLE-CORE-RESOURCE_DETAIL-01**：系统 MUST 让所有资源详情页共用同一套「不存在」处理，新增资源类型时无需重复实现。
- **FR-FULL-CONSOLE-CORE-RESOURCE_DETAIL-02**：系统 MUST 用页面自己声明的列表入口作为回退目标。

## 成功标准

- **SC-FULL-CONSOLE-CORE-RESOURCE_DETAIL-01**：抽查 5 个不同资源的详情页，全部页签可切换且地址栏同步，0 个未翻译 key。
- **SC-FULL-CONSOLE-CORE-RESOURCE_DETAIL-02**：5 个不同资源的失效链接都在 3 秒内回退到各自列表，且列表的集群 / 命名空间上下文正确。

## 明确不做

- 不做详情页之间的「上一个 / 下一个」导航。
- 不做页签级 404 的回退。
- 不为每种资源单独实现一套「不存在」页面。

## 假设

- 每个详情页都通过 `DetailPage` 渲染，并传入 `breadcrumbs`。
