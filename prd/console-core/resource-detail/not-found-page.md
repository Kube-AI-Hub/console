# 404 兜底页（L3）

[子模块需求](./_index.md)

## 概述

新 UI 对未知路径给出**页面不存在**：说明为什么没有内容，并提供返回工作台的入口。

老 console 有兜底路由（`routes/index.js:162`）；新 UI 此前没有——未知路径会落进一个**只有侧栏、没有内容**的空白壳。对使用者来说，「空白」和「坏了」没有区别；而一个来自老 console 的过期书签正好落在那里。

## 用户故事

### US1 - 打开过期链接时知道发生了什么 (Priority: P2)

作为 **使用者**，我希望 **打开一个不存在的地址时看到明确说明**，以便 **不去怀疑系统坏了**。

**Independent Test**：访问一个不存在的 `/kube-frontend/...` 地址，页面出现「页面不存在」与返回入口。

## 验收场景

- **AC-L3-CONSOLE-CORE-RESOURCE_DETAIL-NOT_FOUND_PAGE-01** — 已知地址 `/kube-frontend/this-page-does-not-exist` 没有对应页面，当访问它时，则显示标题「页面不存在」、一句说明与「返回工作台」链接（指向 `/kube-frontend`），而不是空白页。

## 设计目标

1. 任何未被路由认领的路径都落到同一个页面。
2. 该页面保留外壳（侧栏仍可用），因为使用者往往需要从错误地址继续导航。

## 约束与边界

- 只对前端路由：API 的 404 仍由各页面的错误面板处理。
- 不做重定向（不知道用户本来想去哪；猜一个地址比说明更糟）。

## UI 交互设计

- 居中：标题、说明、返回链接。
- 返回链接指向工作台。

## 文案与校验

- 标题「页面不存在」；说明「这个地址没有对应的页面。可能是链接过期，或该功能尚未迁移。」
- 无输入、无校验。

## 边界情况

- 未登录访问未知路径：仍先走登录门，登录后落到 404。
- 深层路径（多段）：同样命中 catch-all。

## 明确不做

- 按旧地址做映射重定向：老 console 的地址与新 UI 的差异不止前缀，猜映射会制造更难查的错误。
- 「最相似页面」推荐：需要全量路由索引与相似度设计，收益不明。

## 假设

- 路由库的 catch-all 能覆盖 `/kube-frontend` 之外的路径。

## 功能需求

- **FR-L3-CONSOLE-CORE-RESOURCE_DETAIL-NOT_FOUND_PAGE-01** — 未知路径统一落到 404 页并保留外壳。

## 成功标准

- **SC-L3-CONSOLE-CORE-RESOURCE_DETAIL-NOT_FOUND_PAGE-01** — 任何未定义路径都显示该页，标题与返回链接存在。

## 验收用例

- `TC-L3-CONSOLE-CORE-RESOURCE_DETAIL-NOT_FOUND_PAGE-01`
