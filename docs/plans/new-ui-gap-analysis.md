**页面级已经基本对齐，缺口全部转移到能力级。**

### 0.4 最要紧的 8 条

1. **集群级 8 类负载 + 配置 3 页 + 网络 2 页是纯只读**：创建（先选项目）、编辑信息、编辑 YAML、重新部署、停止/启动、删除、批量操作全部缺失——集群管理员看得到、改不了，必须先进项目。
2. **全命名空间「按项目筛选」缺失**：负载 8 + 配置 3 + 网络 2 共 13 页只剩关键字搜索，老 `ProjectSelect` 无替代；大集群下不可用。
3. **自制 CRD 应用（composing）整块缺失**：登记的「→扩展资源 别处承接」不成立——扩展资源是通用 CRD 浏览器，没有聚合健康、组件下钻、流量治理、链路追踪。
4. **通知渠道没有筛选条件**：六渠道页面都交付了，但 `alertSelector.matchExpressions` 未实现，**所有渠道对全部告警发送**。
5. **CronJob 运行记录 + 容器组「调度信息」页签未迁**：前者是定时任务唯一的历史入口，后者是老 Pod 排障的第二现场。
6. **工作台从「仪表盘」退化成「项目入口」**：版本、集群数、资源统计、最近访问、东巴入口六类卡片全无。
7. **流水线只能写 Jenkinsfile**：图形化 StepsEditor 与制品/提交/代码质量/PR/任务状态六类页签缺失。
8. **全局工具箱（KubeTools 悬浮球）无对应物**：6 个运维工具没有任何一屏能一起触达。

## 1. 方法与证据边界

### 1.1 判定口径

| 归宿 | 判据 | 本次如何取得 |
| --- | --- | --- |
| 已交付 | 新 UI 有实现，且能指到文件与行 | 读新源码，不只看路由存在 |
| 部分交付 | 页面在，但字段/动作/页签收窄 | 逐项对照老源码与实现 |
| 待补 | 承认没做，无批准 | 计入分母 |
| 批准不做 | 有登记理由（PRD「明确不做」/ design DEC / 能力矩阵） | 只核对理由是否仍成立 |
| 环境阻塞 | 代码已交付，环境不可验收 | 保留证据与复查条件 |
| 未核实 | 本轮没读到足够证据 | **不判缺，也不判有** |

**三条纪律**（来自[迁移指南](../legacy-ui-migration-guide.md)）：
1. **页面级 ✅ 只说明路由存在**（§3.3）——本次所有结论都落到原子能力。
2. **判定能不能做要探测接口，不读模块开关**（§2.3）——2026-11-14 有 3 条结论正是死在「模块开关=接口开关」上。
3. **不要把「新实现、新 PRD、新测试互相一致」写成「与旧版完整一致」**（§6）。

### 1.2 证据边界（必须随结论一起读）

- 本轮是**静态源码判定**：没跑 dev server、没开浏览器、没跑 E2E。
- 「已交付」= **有实现代码**，不等于 E2E、部署环境、member 集群、主题与视觉已验收。这些分别记录在 `capability-matrix.md` §0 的「已有批次证据」与各批次记录里。
- 环境阻塞项（节点 shell、通知投递、etcd 序列、灰度状态、构建器 RBAC 等）保留在能力矩阵，**不从分母删除**。
