# 安装弹窗 · 企业空间与项目的有效组合

> 修复 `APP_STORE-INSTALL-01` 长期失败背后的真实产品缺陷。日期 2026-11-16。
> 规格：prd|design/kube-frontend/app-store/detail.md（AC-INSTALL-03、DEC/GOT-03）。

## 1. 现象与根因

`APP_STORE-INSTALL-01` 在安装成功后**重新打开**弹窗验证「同名安装被拦截」时失败：提交被本地校验拦下，
提示「请选择项目。」。排查后发现两个独立问题：

| 问题 | 根因 |
| --- | --- |
| 切换企业空间后项目仍是上一个空间的 | 项目自动填充只在「项目为空」时发生；切换空间不清空项目，组合无效 |
| 弹窗重开后项目为空 | 弹窗每次打开都会重置；默认选中企业空间列表第一项（本部署是 `public`，**它没有项目**），项目因此为空 |

第一个是**产品缺陷**（可能把应用装进错误的空间，或被服务端拒绝），第二个是**数据现状**（页面如实提示选择项目，
不应自己编一个）。

## 2. 修复（`AppInstallDialog`）

1. **企业空间一变，项目立刻清空**（不等项目列表刷新），避免带着无效组合提交；
2. **项目列表是权威**：选中的项目不在当前列表里就回落到首项；列表为空时保持空，由提交前校验提示「请选择项目。」。

## 3. 用例侧的配套修正

- `INSTALL-01` 的目标企业空间偏好加上 `('system-workspace','default')`：原偏好 `public/spaces`、`public/csghub`
  在本部署已不存在（共享环境的项目被清理），会退到系统命名空间；
- 同一用例在**重新打开弹窗**时重新选择目标组合（弹窗重置是正确行为，用例不该假设它会记住）；
- 新增 `INSTALL-03`：专门覆盖「切换空间后项目清空 / 回落到新空间首项 / 无项目空间提交被本地拦截且不发请求」。

## 4. 实测（B200 host，admin）

| 步骤 | 结果 |
| --- | --- |
| 选 `system-workspace` | 项目自动回落为 `istio-system`（该空间首项） |
| 切到 `public`（0 个项目） | 项目被清空，没有保留 `istio-system` |
| 在 `public` 填名称后提交 | 本地提示「请选择项目。」，**没有任何创建请求** |

## 5. 验证与证据

| 项 | 结果 |
| --- | --- |
| `APP_STORE-INSTALL-01` | **passed**（24.69s，安装成功 + 同名拦截 + 清理） |
| `APP_STORE-INSTALL-03`（新增） | **passed**（8.50s） |
| app-store 串行回归 | 见下方结果 |
| console-next tsc / vite build | 0 error / ✓ |

此前记录的「环境数据漂移」结论在本轮被修正为：既有数据缺失（`public` 无项目），也有产品缺陷（切换空间不清项目）。
两者都已处理。
