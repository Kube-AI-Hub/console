# 颜色令牌契约（浅色/深色主题）2026-11-16

> 新增 `kube-frontend/config/colour-token-contract.test.ts`（5 条）。目的：把「浅色主题下某处发黑/发白」这类
> **只能靠肉眼发现**的问题变成机械检查。

## 1. 令牌分两层

`packages/ai-kit/src/styles/tokens.css` 定义：

- **原始色阶**：`--ai-raw-navy-800`、`--ai-raw-ice-600`…——固定颜色，**不随主题变**；
- **语义令牌**：`--ai-bg`、`--ai-fg`、`--ai-surface-1`、`--ai-accent`、`--ai-line`…——在
  `:root`、`:root[data-theme='light']`、`[data-accent='violet'|'green'][data-theme='dark'|'light']` 各块里重定义。

页面必须只用语义层。直接写原始色阶的后果就是：切到浅色主题那一块仍然是深色值（或反之）——**类型检查完全不报**。

## 2. 五条断言

| 断言 | 防的问题 |
| --- | --- |
| 语义令牌与浅色块存在 | 令牌被误删/改名，或浅色主题块丢失 |
| 应用代码里没有字面颜色（`#hex`、`rgb(31, …)`、`hsl(`） | 写死颜色，两种主题都不变 |
| 每处 `rgb()/rgba()` 参数必须含 `var(--ai-…)` | 用计算出来的数字拼颜色，绕开令牌 |
| 原始色阶只允许出现在登记的例外文件 | 语义层被绕过 |
| 例外清单必须诚实（文件存在、仍在使用、写了理由） | 例外清单腐烂成「什么都允许」 |

当前唯一的例外是 `pages/platform/PlatformInfoPage.tsx`：外观设置里每个色板要显示**它自己**的颜色，
用语义 token 只会显示当前生效的那个色板——这里的原始色阶是正确用法，已在清单里写明理由。

## 3. 反向验证（证明契约真的会拦）

往 `WorkspaceQuotaPage.tsx` 末尾追加 `export const TEMP_COLOUR = "rgb(31, 41, 55)";`，契约立刻两条失败：
「把颜色写死了」与「rgb() 不是来自设计令牌」；恢复后全绿。

## 4. 结果

| 项 | 结果 |
| --- | --- |
| 应用代码中的字面颜色 | **0** |
| 非令牌 `rgb()/rgba()` | **0** |
| 原始色阶例外 | 1（有理由、有反向守卫） |
| 契约套件 | **13 个文件 / 1459 passed** |

## 5. 边界

契约只能保证**用的是语义令牌**，不能保证「语义令牌在浅色下取值合理」——后者仍需目视（浅色主题截图），
在 B200 链路可用时补。
