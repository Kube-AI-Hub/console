# 新 UI 迁移执行路线

> 当前执行路线，2026-11-15 原地整合。只维护优先级和执行顺序，不再追加逐轮进度。
> 方法以[迁移指南](../legacy-ui-migration-guide.md)、规格以 [SDD](../SDD.md) 为准；
> 当前复核任务只在[能力矩阵](capability-matrix.md)维护。旧路线可从 git 历史查询。

## 边界与基线

- 真实环境使用 B200；本地全栈与部署环境分别验证，不能用前者代替后者。
- 多集群部署（如 A100 的 `host` + `xc`）要单独判定：成员集群的路径、写入归属与「读不到」状态见[架构宪法 C6](../constitution.md)与[验证手册](multicluster-playbook-20261117.md)。
- 老代码用于盘点行为和接口；新实现避免复制 AGPL 源码。目标仓库的许可证兼容性、
  依赖及历史代码的许可结论须由项目方审核，不能仅凭重新实现认定合规。
- 路由、骨架或模块已开启均不能证明子页、权限、写能力和视觉已完成。
- [GAP](new-ui-gap-analysis.md) 与 `_gap` 只是历史线索，不能按旧缺口数量从头重迁已经交付的页面。
- 先检查现有实现和并行修改，再选定一个用户任务及其完整页面范围；不把模块开关或历史故障当成实时事实。

## 执行顺序

| 优先级 | 范围 | 开始前核实 | 完成条件 |
| --- | --- | --- | --- |
| 0 基线复核 | 所有候选页 | 代码、规格、并行边界、实际 API、独立旧能力清单 | 未映射项可见；选页依据明确，不复制历史总量 |
| 1 安全与运维 | 权限、角色、终端、日志、关键资源写入 | 已有实现与实际角色；无 stdout/403/控制器异常 | 当前缺口按任务关闭，保留已完成控制台交互，不切生产 GPU 模式 |
| 2 日常任务 | 工作负载、网络、存储、成员及列表交互 | 完整入口/子页/表单/分页/筛选范围 | 功能、数据、交互与视觉同批验收，写入回读且清理 |
| 3 数据与监控 | 概览、GPU/RDMA、用量排行、图表 | 指标/标签/单位/全局范围与旧完整选项 | 请求→映射→展示对账；同批主题/布局检查，不新增缩水版概览 |
| 4 新开启区域 | DevOps、联邦项目、商城、灰度等 | 已有只读列表/骨架与真正任务差距 | 列表不等于完整区域；每页按模板验收，不能因入口已有宣称全迁 |
| 5 发布收口 | 已通过本地验收的范围 | 全仓基线问题、共享回归、实际部署目标 | 全站串行与部署复核分别完成，未验收范围明确列出 |

优先级不是当前完成状态。未进入本批的候选页仍在能力矩阵，不能把路线表当作已验证清单。
同页内部可分任务编码，但最终一次交付须覆盖已约定的子页、动作、状态及视觉。

## 一页的执行顺序

1. 选页并填写[交付模板](page-migration-template.md)的基线、旧能力全集、显示条件、选项、子页面和角色。
2. 对照实际请求建立数据链路；在同一模板中定义信息层次、字段栅格、主题参考与组件复用。
3. 旧能力逐项关联完整 AC/DEC/TC，视觉与数据断言一起进入规格；待核实项不得改成“不做”。
4. 独立编码，保留既有功能与句柄；新增/扩展共享组件才补 Storybook API 示例及组件回归。
   跨页面行为问题（滚动、关闭、焦点、错误可见）优先修在共享层，一处覆盖全部页面。
5. 固定本批构建，分别跑静态、显式类型/构建、单测、相关及共享影响的串行 E2E，
   同次响应对账并人工比较新旧首屏/全页、展开状态及三档布局。
   改多处同类问题时，单测跟着改动走、浏览器验证攒到最后批量跑，用同一批构建一次覆盖。
6. 能力覆盖、数据语义、交互权限、视觉主题、验证/部署范围分别结论；未通过则不关闭对应行。
7. 只更新能力矩阵对应项和该页证据，不再在多个历史计划末尾追加同一进度。

## 暂停与恢复

接口、权限或环境阻塞时，留下具体请求/版本/角色/日期、证据、影响项及复查条件。
该页保持部分完成/阻塞，不能以缩 AC、空数据填0、模拟响应或别页存在关闭缺口。
恢复后在同一交付记录继续原能力 ID，不重新建立缩水清单。
遇到并行修改直接冲突先协调；不得恢复、覆盖或提交他人的未确认改动。

并行方在改同一批文件时，提交前按文件逐个 `git diff` 确认归属；无法确认的**不要提交**，
在回复里列出文件名与它属于哪个批次，由对方决定。混入并行改动会让一次提交同时包含两个方向
未完成的改动，回滚时无法只回一个。

## 历史进度的去向

旧路线的列表、创建、终端批次叙述及“仍缺”判断已退出当前排期正文，保留在 git 历史。
具体进度看能力矩阵，测试看对应批次记录；两次概览复盘见
[功能遗漏](cluster-overview-parity-review-20261115.md)与[视觉返工](cluster-overview-layout-review-20261115.md)。
原能力、共享控件、数据与视觉必须在本页首次完整交付时一起检查，不把复盘当作常规补漏环节。
