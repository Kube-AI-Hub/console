# 修掉两个对比度缺陷：新增文字专用链接色令牌（2026-11-16 第 53 轮）

> 上一轮渲染审计抓到两处不达标；本轮修掉，并把「已知缺陷清单」清空（清单为空的守卫仍生效）。

## 1. 根因

`--ai-accent` 是**填充色**：填充只需要和「什么都没有」对比，文字要和背景对比。
把填充色当文字色用在不那么深的表面上，就只有 **2.84:1**。

## 2. 修法：新增 `--ai-link`（按主题各取一步）

| 主题 | 取值 | 最差比值（该主题各表面） |
| --- | --- | --- |
| 默认/深色 | `violet-500` | 5.20 |
| 浅色 | `violet-100` | 4.68 |
| 紫/深 | `violet-500` | 5.20 |
| 紫/浅 | `violet-100` | 4.68 |
| 绿/深 | `mint-400` | 7.31 |
| 绿/浅 | `mint-700`（新增原始色阶 `10 110 85`） | 5.01 |

同时把浅色主题的 `--ai-success` 从 `0 138 92`（4.07:1）改为 `10 110 85`（5.01:1）。

接线：`tailwind.preset.ts` 暴露 `link` 颜色 → ai-kit 的 `Button` link 变体用 `text-ai-link`；
应用里 75 个文件里**链接形态**的 `text-ai-accent`（`… hover:underline`、纯文本链接）改为 `text-ai-link`，
**填充/边框/带透明度的**用法保持 `--ai-accent` 不动。

## 3. 一个几乎毁掉结论的编辑事故

第一次插入 `--ai-link` 时，脚本用 `indexOf(":root[data-theme='light']")` 定位——它**先匹配到了上方注释里的同一段文字**，
于是把声明插在了注释与选择器之间，形成一条**游离在规则外的声明**。

后果不是报错，而是：CSS 解析器在恢复错误时**丢掉了紧随其后的整个浅色主题块**——
浅色页面因此拿到了深色的 `--ai-fg`（`rgb(222,235,246)` 配浅背景 = **1.13:1**），
5 个浅色用例全线失败。

**教训**：用 `indexOf` 定位 CSS 块必须匹配**行首的选择器行**（`^:root…{$`），不能匹配任意出现；
而且插入后要**回读文件**确认落在块内。这次正是回读 `sed -n` 输出才发现的。

## 5. 顺手暴露的第三个缺陷（已登记，未修）

把 `--ai-surface-3`（悬停行背景）纳入令牌契约后，发现 `--ai-fg-secondary` 与 `--ai-link` 在其上分别是
**3.97** 与 **4.01**，都差一点。修它需要为悬停态单独定一个文字色阶，会牵动每个表面，
因此登记为 `KNOWN_TOKEN_GAPS`（带实测比值 + 双向守卫：修好后契约会失败提醒删除）。
