# 悬停表面上的文字也达标了（2026-11-16 第 54 轮）

> 上轮把 `--ai-surface-3`（悬停行背景）纳入令牌契约时暴露了两处差一点：`--ai-fg-secondary` **3.97**、
> `--ai-link` **4.01**。本轮修掉，`KNOWN_TOKEN_GAPS` 清空。

## 1. 为什么改背景而不是改文字

两条路：调亮文字，或调暗悬停背景。

调文字会影响**所有**表面上的次要文字（每处都跟着变），而悬停背景只在一种情形下出现。
而且语义上更对：悬停只是「抬起一层」，不该亮到让文字读不清。

## 2. 取值

在 `navy-500`（58,73,143，`--ai-surface-2`）与 `navy-400`（74,90,162）之间新增一步：

```css
--ai-raw-navy-450: 62 77 148; /* #3e4d94 */
```

| 候选 | fg-secondary | link | muted |
| --- | --- | --- | --- |
| navy-400（原来） | 3.97 | 4.01 | 4.75 |
| **navy-450（采用）** | **4.82** | **4.88** | 5.77 |
| navy-500 | 5.14 | 5.20 | 6.15 |

选 450 而不是 500：`--ai-surface-2` 已经是 500，若悬停也用 500，「抬起的一层」与「卡片面」就没有区别了。
第一版试了 66,81,152（4.54），离阈值太近，又往深处走了一步到 4.82。

## 3. 双向守卫又生效了一次

改完先跑契约，它立刻报：

```
--ai-fg-secondary on --ai-surface-3 现在通过了（4.54:1），请从 KNOWN_TOKEN_GAPS 删除
```

**这正是这条守卫存在的意义**：修复后如果忘了删登记，套件会提醒；反之如果登记项悄悄失效，也会失败。
清空清单后又发现一个自检缺陷——`Math.min(...[])` 是 `Infinity`，把「无缺口」的底线断言写坏了；
已改为「有登记时用登记下限，无登记时必须整体 > 4.5」。

## 5. 流程反思：这一轮做对了什么

1. **先量后改**：三个候选值都先算出四个比值再选，而不是改完看测试；
2. **改在影响面最小的地方**：动背景而不是动全局文字色；
3. **让守卫替我记事**：清单清空由契约提示，不靠记忆；
4. **自检也要有边界用例**：空清单这种「一切正常」的状态同样需要断言，否则修复后反而报错。
