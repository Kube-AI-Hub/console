# ResourceList 的两个空态改进，在 Storybook 上验过了（2026-11-18）

## 背景

本轮给共享组件 `ResourceList` 加了两件事：

1. **区分「没有匹配」与「本来就没有」**（收窄时标题换成「没有匹配的结果」）；
2. **空态里渲染页面的主操作**（与页头同一个按钮、同一个回调）。

两件都在页面里验过（`xc` 配置字典搜空、守护进程集空列表），但**共享组件的行为应当有 story**——
迁移指南 §7 的要求是「新增/扩展公共组件时补故事和组件测试」。

## 新增 story

`stories/ResourceList.stories.tsx` 增加 `NoMatch`：固定渲染「被搜索收窄」的那一支，
页面自己给的 `empty.title` 是「还没有工作负载」，用来证明它**没有**被误用。

## 验证（Storybook 6106，无需集群）

```
body: 工作负载 | 输入一个不存在的名字，看空态说的是什么。 | 创建 | 没有匹配的结果 | 创建 | 清空搜索与筛选
has create: 1              ← 页头主操作
has empty primary: 1       ← 空态里的同一个主操作
```

| 断言 | 结果 |
| --- | --- |
| 收窄时显示「没有匹配的结果」而不是页面的「还没有工作负载」 | ✓ |
| 空态里有主操作（`empty-state:primary`） | ✓ |
| 仍有「清空搜索与筛选」 | ✓ |
| `tsc` | 0 |

## 反思

共享组件的两个行为改动，此前只有页面级证据；story 让它们**不依赖集群也能复现**，
也让「页面的空态文案不该在收窄时出现」这条约束有了可见的对照。
