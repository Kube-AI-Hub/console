> 规格：prd|design/kube-frontend/configmaps/list.md（AC-CONFIGMAPS-LIST-10、DEC/GOT-10）。

## 1. 本批范围（6 个列表）

| 页面 | 分页方式 | 结果 |
| --- | --- | --- |
| 集群告警消息 | 服务端 | 默认 20，选 50 → `limit=50`，50 行 |
| 集群告警策略 | 服务端 | 档位接入（当前 18 组不足一页，分页器与选择器不渲染） |
| 集群快照类 | 服务端 | 选 50 → `limit=50`（当前 0 对象） |
| 集群资源监控排行 | 客户端 | 档位接入；切换后行数 ≤ 50 |
| 工作空间配额 | 客户端 | 档位接入（数据不足一页时不渲染分页器） |
| 工作空间角色 | 客户端 | 同上 |

## 2. 本批修掉的两个缺陷

1. **工作空间配额的切片仍用常量**：`paged = rows.length > PAGE_SIZE` 与切片都写死常量，档位形同虚设；
   改为跟随 `pageSize`。
2. **分页器缺 `sortAiPrefix`**（集群告警消息/策略、工作空间配额/角色）：分页器与档位选择器的 `data-ai-id`
   由该前缀派生，缺了它选择器在页面上存在但自动化找不到。

## 3. 一个刻意的「不渲染」

数据不足一页时不渲染分页器，因此也没有档位选择器——这与旧 console 一致，强留会造出「选 50 条但只有 4 条数据」的死控件。
用例对这种页面显式跳过（并注明原因），不把它当失败。

## 4. 累计

- 已接入档位：**26 个列表**（项目侧 4、集群侧 8、监控/平台/设置/联邦/商店/构建器 8、本批 6）。
- 明确不适用：应用商店浏览页（`load more` 模式，无分页器）、日志/事件/审计页（按 limit 取最近 N 条、无分页器）、登录历史面板（服务端分页但当前数据不足一页）。
