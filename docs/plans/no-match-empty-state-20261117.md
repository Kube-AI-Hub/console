# 「没有匹配的结果」与「暂无数据」是两个答案（2026-11-17）

## 1. 缺口

全仓 **44 个带搜索框的列表里，只有 3 个**区分了「列表本来就是空的」与「搜了但没匹配到」。
其余 41 个在搜索无结果时仍显示页面自己的空态文案，例如：

```
搜索 zzz-no-such-thing  →  「暂无配置字典 / 请创建一个配置字典。」
```

这句话回答的是「这里什么都没有」，而读者问的是「我搜的东西在哪」。

## 2. 修在共享层，而不是 44 个页面

`ResourceList` 现在自己判断「当前是否被搜索/筛选收窄」，并据此选文案：

```tsx
const narrowed = Boolean(searchValue) || Object.values(filters ?? {}).some((v) => v !== '' && v !== undefined);
title={narrowed ? schema.empty?.noMatchTitle ?? '没有匹配的结果' : schema.empty?.title ?? '暂无数据'}
```

- 页面可以提供 `empty.noMatchTitle` / `noMatchDescription` 覆盖；
- 不提供时用中性默认「没有匹配的结果」；
- **未被收窄时完全不变**，页面的空态文案照旧。

## 3. 一个关键细节：优先级不能反

第一版写成 `(narrowed ? noMatchTitle : undefined) ?? empty.title ?? …`，结果**没生效**——因为页面提供了
`empty.title`，`??` 在它那里就停下了，默认值永远轮不到。浏览器实测搜索后仍显示「暂无配置字典」。

正确写法是让 no-match 分支**整体优先**：`narrowed ? (noMatchTitle ?? '没有匹配的结果') : (title ?? '暂无数据')`。

## 4. 验证

| 检查 | 结果 |
| --- | --- |
| 搜索无匹配（`xc` 配置字典页） | **「没有匹配的结果」**（修复前「暂无配置字典」） |
| 未搜索、列表为空 | 页面自己的空态文案不变 |
| 契约套件 | 18 文件 / 1544 passed |
| `tsc` / `vite build` | 0 / ✓ |

## 5. 反思

| # | 规则 |
| --- | --- |
| 1 | **共享层的默认值要能压过页面值**，否则等于没改——`??` 链的优先级是最容易写反的地方 |
| 2 | **改完必须在浏览器里搜一次**：类型检查与单测都不会告诉你「文案没变」 |
| 3 | 一处改动覆盖 44 个列表，比逐页补 41 次可靠得多 |
