# 集群概览布局优化与再次复盘

> **历史视觉交付证据。** 本文保留四项调整、三档截图和当时验证边界，不作为实时错误或待办清单。
> 同批完整交付的方法已整合至[迁移指南](../legacy-ui-migration-guide.md)与[单页模板](page-migration-template.md)，
> 当前复核任务只维护[能力矩阵](capability-matrix.md)；不再依靠迁移后重复复盘补漏。

## 范围与结论

承接[功能补齐记录](./cluster-overview-completion-20261115.md)，本轮按用户四项要求优化布局，
不复制旧 AGPL 组件，不增加生产写操作。验证地址为
`http://localhost:5178/kube-frontend/clusters/host/overview`，本地新版通过 BFF 读取 B200。
功能补齐和视觉验收分开记录，不以单测或同名区块存在证明页面已经完整、整齐。

| 要求 | 本轮实现 | 验收方式 |
| --- | --- | --- |
| Kubernetes 状态同列 | 左列依次为基本信息、Kubernetes 状态、模块 | 检查父容器及相邻 DOM 顺序，三档截图复核 |
| 资源字段对齐 | 名称、已使用、总量、使用率、已分配采用固定栅格；无分配能力留空，不显示标签 | 七类资源逐字段句柄与相对坐标，1024/1280/1600 下偏差小于2px |
| 去掉 GPU 额外行 | 删除额外 GPU 利用率文本；保留实际使用卡数、总数、使用/总量比例、分配卡数 | 单测及浏览器检查额外文本不存在，数据对账仍保留 |
| 重点与直观性 | 标题、资源、组件、工具采用 ai-kit Icon；使用率与 Top5 使用共享 Progress | 图标不替代文字；百分比排行显示小条，load1 不画百分比条 |
| 主题边框 | 区块统一 rounded-ai-lg、border-ai-line、bg-ai-surface-1；资源内卡使用 surface-2 | 与 gpu02 节点基本信息实际 computed borderColor 比较，不只查 class |

资源区优先显存与 GPU；值使用等宽数字，真实零保留，未知值不伪造为零。
无分配字段保留空区域用于对齐，不输出“已分配”空标签。较窄桌面的系统组件使用两列，
1280及以上三列，避免英文名称挤压。原工具、组件分类、九维排行与 kubeconfig 安全交互保留。

## 为什么仍需再次调整

1. 前轮主要关闭功能缺口，验收强调字段与动作是否存在，没有把区块所在列、相邻顺序和字段坐标列为要求。
   因此“数据齐全”并不等于“信息层次清楚”。本轮新增 AC-07 和 OVERVIEW-06，独立验收视觉。
2. 资源卡此前合并已用/总量文字，且 GPU 有额外可选行。不同卡的行数与文本长度不同，
   靠统一外边距不能保证值、比例和分配量对齐。改为固定字段栅格，而不是填零或复制无意义标签补高度。
3. 概览旧 Panel 混用 border-ai-border/bg-ai-surface，与节点使用的 line/surface-1 不一致。
   本轮统一主题 token，并以浏览器计算色与参考页面对账，避免构建通过但渲染颜色不一致。
4. 新增图标与条形展示后仍需人工看截图。1024截图暴露系统组件英文名称换行，
   因而调整响应式列数；自动化坐标检查不能替代可读性判断。
5. 真实排行响应含无 metric/node 标签样本，原测试直接索引导致 KeyError。
   API 已过滤无身份样本；本轮测试按节点身份过滤、去重，保留目标指标顺序及其他有效节点，
   同时补 API 夹具，不跳过排行验收，也不把缺标签样本当作节点。

GPU 额外利用率文本移除是用户批准的展示优化，不再登记为迁移遗漏。
这不等于删除 GPU 使用量或排行中的 GPU 利用率能力，也不改变 API 字段契约。
旧设计“第二行利用率”的理由保留为历史，并显式标记后续决策覆盖。
本轮使用现有 ai-kit 图标和进度条即可完成，没有新增公共组件或属性，因此无需新增 Storybook API 示例。

## 验证与边界

- 概览 OVERVIEW-01 至06 六条串行浏览器回归通过：原数据、未知值、组件、工具、安全配置及排行回归保留。
- 关联页 NODE_USAGE-01、COMPONENTS-01、COMPONENT_DETAIL-01 三条串行回归通过。
  完整排行同步修正无节点标签样本解析；未知字段显示 `-`，有效 CPU/内存/磁盘值仍逐项核对百分比换算和服务端排序。
- 应用全量单测175条、API全量单测290条通过，包含局部应用7条和API补齐5条；本地构建通过。
  应用单测有既有 CodeMirror/jsdom getClientRects 警告，不等于真实浏览器失败。
- 概览旧能力清单、一致性及包边界共25条通过；局部严格规格门禁 errors=0、warnings=0。
- 三档截图人工复核；无页面横向溢出，字段坐标一致，主题边框与节点详情一致。
- 本轮覆盖当前深色主题的计算色比较，未声称验证所有主题、语言或移动端。
- 应用全量类型检查仍被未修改的 AppStoreAppDetailPage.tsx 两处 TS2367 阻塞，
  API全量类型检查仍有前轮记录的两处夹具错误；构建通过不等于全仓类型检查通过。
- 未执行全站串行 E2E，未部署生产，未验收真实 member 集群。

截图中的集群属性与节点数量为采集时的实时环境状态，不代表迁移代码写入。
排行的超过五节点截断、完整页分页用12节点模拟；真实 kubeconfig 不入截图或日志，
下载内容和403仍使用非敏感模拟。历史采样不能用于断言当前节点数量或动态用量不变。

## 防止再次发生

- PRD同时写字段语义与信息层次，design说明可选字段如何保持布局，YAML与Python覆盖两者。
- 视觉变更保留原字段对账、安全和交互回归，不用截图存在替代数值验证。
- 先看目标主题的 computed style，再复核三档全页截图；不能只以 token 名称相似认定一致。
- 用户批准的不迁移或展示删减必须记录范围，避免后续把刻意移除误当成缺失。
