## 2. 实现要点

- 两张 `TrendChart` 并排而不是一张双轴图：CPU 是核（0.1–2 量级），内存是字节（10^9 量级），同一纵轴会把 CPU 压成贴底直线。
- 时间窗决定 `step`：1h 用 60s（约 60 点），6h/24h 放大到 300s（约 72/288 点），避免 24h 取 1440 点。
- 区间在窗口变化时才解析（`useMemo` 依赖窗口），否则每次渲染都换查询键会无限重取。
- 采样里的 NaN/Inf 直接丢弃：曲线上的断点，而不是 0。

## 3. 踩到并修掉的问题（工具链）

批量插入代码片段时用了 `String.prototype.replace(marker, text)`，而插入内容含 `` $` ``（模板字符串里 `$` 紧跟反引号）——
替换参数把它解释成「匹配前的整段文本」，于是把文件前半部分吸进了模板字符串，`tsc` 报 46 个语法错误。
改用 `split(...).join(...)` 后一次通过。已记入 design 的 GOT-05，作为后续批量改代码的规则。
