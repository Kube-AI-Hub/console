# 单页迁移交付模板

> 当前模板，配合[迁移指南](../legacy-ui-migration-guide.md)使用。复制到该页的迁移记录，
> 填入真实证据后删除提示文字；它不是第二份 PRD，不在此重新定义 AC 或组件 API。
> 原子能力表先从旧源码/部署行为建立，再关联新 AC，不能从新 PRD 反推旧能力全集。

## 1. 范围与基线

| 项 | 本页记录 |
| --- | --- |
| 用户任务、作用域 | 填平台/企业空间/集群/项目，以及用户完成的任务 |
| 旧入口、源码版本、部署 URL | 路由、入口容器、子组件、Store/API；部署与源码不一致时分别记录 |
| 新入口、提交及工作树、构建 | 新路由、相关文件；不能只记录 HEAD 而忽略未提交内容 |
| 环境、集群、角色 | B200/本地/模拟/生产分开，主集群/成员集群不混用 |
| 视口、主题、语言 | 1600×900 首屏及全页；1024/1280/1600，声明实际覆盖的深浅色/色调/语言 |
| 子页面与状态范围 | 详情/页签/下钻/创建/编辑/删除/工具弹窗、条件入口 |
| 明确排除及批准 | 逐项写范围、理由、批准依据；阻塞不写成批准不做 |
| 并行文件与安全边界 | 所属修改、可协调共享文件；禁止的生产写入与敏感信息 |

默认范围包含现有支持的深浅主题、色调与中英文，以及旧页面条件成立时的角色分支。
不能为了少验收而把既有支持范围删掉；环境限制可标未验收，但相应维度只能结论为部分通过。

## 2. 旧能力全集与归宿

每行只描述一个可以单独判断的字段、动作、状态或选项；示例 ID 改成本页自己的稳定 ID。
允许多行关联同一 AC，但每一行仍须有可核对的断言。不要写“资源用量已迁移”之类整块结论。

| 旧能力 ID | 源码/部署证据 | 显示条件/角色 | 字段、动作、默认项与完整选项 | 归宿/新位置 | 新 AC/用例/具体断言 | 实现与验收状态 |
| --- | --- | --- | --- | --- | --- | --- |
| LEG-page-001 | 路径、组件和采集证据 | 条件成立与不成立两分支 | 一个原子事实 | 保留/改进/批准不做/等价承接/待补 | 完整 AC/TC ID + 验证内容 | 待实现/待验证/通过/阻塞 |

检查表：

- [ ] 路由、下钻、动态子页签、右键/更多菜单、展开下拉、折叠区和默认隐藏入口均已清点。
- [ ] 列表的列/默认排序/筛选项/分页档位/全局总量、详情的属性/页签/操作、表单的字段/校验时机均拆开。
- [ ] 加载、真实空、无匹配、错误、无权限、未就绪、缺值与真实零各有归宿。
- [ ] 所有旧能力已映射；无未经证明的承接、无未经批准的删减。新增能力单列，不能抵消旧能力缺失。

## 3. 数据契约与全链路

| 能力 ID | 请求路径/版本/作用域/参数 | 字段或指标/标签 | 原单位→显示单位/精度/分母 | API 映射→页面位置 | 缺值/零/异常/过期值规则 | 同次响应对账断言 |
| --- | --- | --- | --- | --- | --- | --- |
| LEG-page-001 | 填实际请求，不据菜单开关猜测 | 例如 result=error | 使用量与分配量独立 | 三段落点均写明 | 无标签样本不能当成对象；NaN 不填0 | 用互不相同的输入，验证标签、单位与显示值 |

- **同一对象可能有两条读路径**：聚合 kapis 读常带 `status`/派生字段，`/apis` 原对象没有。两条路径分别记录字段与
  缺失态；列表、详情、导出必须用同一条路径核对，缺失字段显示 `-`，不用 0 或空串补。

排行补全指标全集、默认项、排序键/方向、全局 TopN、分页 total、身份合并、搜索与下钻参数。
模拟数据至少超过 TopN/一页；缺值、乱序系列、无身份样本单列。模拟证明边界，不冒充真实规模。
跨集群查询与缓存须同时包含作用域，禁止 member 失败后回退为 host 数据。
403/404/空200/瞬时失败分别记录；一次错误只能证明对应请求，不能证明整项产品能力不存在。

## 4. 交互、视觉与复用基线

**参考页要截图存档，并写明复制它的哪一层**（区块布局 / 字号层级 / 密度与分隔线 / 控件形态）。
只写“参考 X 页”不算基线：读组件源码得到的是它自己的写法，不是本页要的方向。
字号层级按**关系**写（“标签大于值，标签中等字重、值次色”），不要先写死像素——
像素是实现细节，回填进 AC 会让“方向对不对”无法判断，改方向时还要连 PRD、生成用例、契约注释一起改。

| 项 | 编码前约定 | 验证断言/截图 |
| --- | --- | --- |
| 信息层次 | 主任务、首屏重点、区块列与相邻顺序 | 首屏+全页，明确位置而非只检查存在 |
| 字段栅格 | 名称/值/单位/比率/可选行的固定位置 | 各断点相对坐标；不存在的字段留空，未知值不能填零 |
| 字号层级 | 标签与值谁大、字重、颜色 token；写关系不写像素 | 关系断言（标签字号 > 值字号），不 `toContain('text-sm')` |
| 密度与铺满 | 区块是否填满槽位、中间是否留白、行间分隔线是否通栏 | 相邻元素 `getBoundingClientRect()` 差值；不靠“看起来” |
| 主题 | 参考页面、语义 token、表面层级、边框、文字与状态色 | 实际 computed style、对比度、深浅主题；未测组合明确列出 |
| 图标与图表 | 不替代文字；空值不画0条；负载色与健康色区分 | 图标可读、进度/轴单位正确、图表内部滚动 |
| 通用控件 | 优先 ai-kit，其次应用公共组件 | 分页/搜索/表单/页签/错误/确认/图表不私造同类结构 |
| 表单与弹窗 | 校验焦点、取消不写、保存反馈、错误保留输入 | 键盘/焦点/关闭清理/二次打开；**错误在滚动容器里必须滚入视野**（滚动量与可见性用 `getBoundingClientRect()` 量）；敏感内容不入截图 |
| 链接与状态 | 同作用域下钻、可中键、点击反馈、刷新反馈 | 全部有效入口实际走通，空态/失败有正确出口 |
| 控制台（适用时） | 独立近全屏、Tab/历史/ANSI/光标/PTY、关闭释放 | 首次 stdout 才就绪，握手101不算成功，Esc 留给程序 |

复用决定：写现有组件是否够用；确需新增/扩展时写公共需求、消费者、兼容影响及 Storybook 状态。
仅组合现有能力时明确无需新增故事，不为了单页新建业务专用公共组件。

## 5. 编码与回归

- [ ] PRD 的 AC 同时承接功能、数据语义、状态、权限、交互与视觉，design 写完整决策及被否方案。
- [ ] YAML 与 Python 一一镜像，句柄稳定；原能力回归保留，视觉调整不以删除数据断言过关。
- [ ] 旧能力表独立比对新实现；可自动检出的遗漏加契约，其他项人工逐行核对，不声称已有通用自动门禁。
- [ ] API/mapper 单测、组件/应用测试、显式类型检查与构建、严格规格门禁分别记录。
- [ ] 固定本批构建并确认 BFF/代理版本；相关及受共享组件影响的 E2E 串行判定。
- [ ] 改共享列表的默认值（页大小/排序/列顺序）前，检索已交付 AC 与既有用例；这些默认值属于用户可见契约。
- [ ] 若改动落在共享层（`Modal`/`Select`/`FormField` 等），列出受影响的其它页面并逐一确认未回归；只验本页不算通过。
- [ ] 失败先 `git stash` 复跑确认是否本批引入；基线失败连命令与错误一并记录。
- [ ] 改过 AC 文案后重跑 `generate_case_docs.py`；grep 旧数字与措辞，清掉 design/story/契约注释里的上一版方向。
- [ ] 写入或接口 5xx 时先按指南 §7.5 判定是前端、apiserver 还是被调组件，再决定改代码还是记环境问题。
- [ ] 实际采样按同次响应核对；边界/写入/403 使用安全数据，测试对象唯一命名且失败也清理。
- [ ] 新旧同角色同集群的首屏/全页、展开状态及三档截图人工复核；不只断言截图文件存在。

## 6. 完成判定与证据

| 维度 | 状态 | 日期/构建/证据 | 未通过或未验收项 |
| --- | --- | --- | --- |
| 旧能力覆盖 | 待填 | 表中总数、通过数、批准不做数、待补/阻塞数 | 未映射、未经证明承接必须为0 |
| 数据语义 | 待填 | 请求→映射→展示及同次对账 | 单位/标签/精度/全局范围 |
| 交互与权限 | 待填 | 实际动作、回读、作用域隔离、连接清理 | 跳过不算通过 |
| 视觉与主题 | 待填 | 断点/主题/语言、人工复核与计算色；`theme-contrast-contract` 的令牌矩阵 + `--keyboard` 的双主题焦点走查 | 不支持或未测组合；焦点环只测「可见」不测对比度数值 |
| 静态/类型/构建/测试 | 待填 | 完整命令、通过/失败/skip、日志位置 | 基线错误也列出，不冒称全仓通过 |
| 本地全栈/B200 读取 | 待填 | 实际上游、用户与集群 | 与模拟证据分开 |
| 新版部署/member/全站 | 待填 | 实际目标地址与验证范围；member 用 `multicluster_sweep.py --baseline` 的读/详情/Tab/写入落点四段 | 未执行明确写未验收；member 上「读不到」与「空」要分别记录 |

计数按原子能力 ID 去重。只有通过项与批准不做项能关闭对应行；
阻塞/待补/未验证不能从分母删除。按声明范围分别结论为“本地该页交付完成”“部分完成/阻塞”
或“新版部署已验收”；不使用没有范围的“全部完成”。
收尾更新[能力矩阵](capability-matrix.md)对应项及后继链接，不在每份历史计划再追加 TODO。
