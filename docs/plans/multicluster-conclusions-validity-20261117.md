## 4. 反思

| # | 规则 |
| --- | --- |
| 1 | **提交前看一眼 `git diff` 里非自己的改动**：`git add <dir>` 会把并行线的改动一起带走 |
| 2 | **结论要标注取证方式**：HTTP 实测 / 浏览器读数 / 读代码——浏览器读数最容易假绿 |
| 3 | 工具出问题后，**先列「哪些结论受影响」再谈修复**，否则会把错误结论继续当依据 |
