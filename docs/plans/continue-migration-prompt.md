## 快速选定范围，不做全量预分析

- 检查当前分支、提交、未提交修改、正在运行的服务与已有验证证据。保留并行工作；直接冲突先协调，不覆盖、不回退他人的改动。
- 用户指定范围时优先完成该范围，不擅自缩成其中几个页面、字段或按钮。未指定时，只看当前台账的标题/状态、路线优先级及相关并行边界，选一个具体、可闭环的迁移单元；不把 CHECK 类聚合条目下的所有模块都纳入本批。
- 完整迁移单元是一项用户任务对应的页面族，例如某资源的列表、详情及其创建/编辑/删除、页签、下钻和工具弹窗。已有能力保持可用，范围内的实际缺口一次补齐；“先做列表或骨架，详情和写入下次再说”不算完成。
- 简短说明本批目标、包含的页面/动作及选择依据，然后立即开始目标范围的深读和实施。不先重建全站 GAP、重新统计全部路由、逐项探测所有待办 API 或编写全站分析报告。
- 候选已完成、被并行方负责或整体阻塞时，才快速检查下一个候选。只对选定单元及必要的直接依赖深读；不无条件扩展到其他模块，不在完成当前单元前切换到一批新范围。
- 验证环境以 `/Users/yuan/code/kube-ai-hub/环境/B200环境.md` 为准。旧站参考 `https://console-dev.brightaitoken.ai`，新站通常为 `http://localhost:5178/kube-frontend`，使用前确认实际服务和构建，不重复启动或误杀他人进程。
- 不根据历史节点数、测试总量、旧故障或模块开关判断当前能力。记录实际路径、版本、角色及请求结果；一次404不证明整个能力不存在。

## 只深读选定单元，并一次完成闭环

1. 编码前仅针对选定单元，按模板建立独立旧能力清单：入口→路由/动态子页→区块/子组件→Store/API→字段、动作、条件、完整选项。检查详情页签、更多菜单、折叠内容、角色分支及默认隐藏入口，不能只看导航或首屏；只追查为完成该单元必需的直接依赖。
2. 每项使用稳定原子 ID，逐项关联新落点、完整 AC/DEC/TC 和具体断言。保留、改进、批准不做、等价承接、待补/阻塞分开；“别页已有”必须证明用户任务、数据、默认筛选、排序、权限和下钻等价。
3. 同时确定数据与视觉基线：请求→映射→展示、指标标签、单位/精度/分母、实际使用与分配量、全局统计/TopN/分页；主任务、区块所在列与顺序、字段栅格、可选行、主题边框、图标和图表。功能与视觉一起进入 AC、一起实现和验收。
4. 独立实现，不复制旧 AGPL 组件源码，不把重新实现等同于许可证合规结论。页面请求统一经 api-client；优先复用 ai-kit 和应用公共组件。现有组件不足才扩展公共 API，补 Storybook、组件测试及消费者回归，不为单页私造同类控件。
5. 按 SDD 同步 PRD、design、YAML 与一一镜像的 Python 测试，保留原能力和安全断言。结构变化才改 `tree.py`/注册表；catalog、cases、追溯矩阵和逐页审计用对应生成器更新，不手改、不强制覆盖手写稿。
6. 固定本批构建后测试：API/mapper 与应用/组件单测、显式类型检查、构建、严格规格门禁、相关及共享影响的串行 E2E。按实际同次响应对账，人工复核新旧同角色同集群的首屏/全页、展开状态和1024/1280/1600截图，覆盖既有深浅主题、色调与中英文。
7. 分别报告旧能力覆盖、数据语义、交互权限、视觉主题、测试/部署范围。只有通过或批准不做才能关闭对应项；阻塞、skip、待补、未验证不能移出分母，新增能力不能抵消遗漏。

内部可以分步骤编码和测试，但不要在首个子页、几个字段、只读列表或骨架完成时就结束本批。
交付前回到本批清单逐行复核：仍可实施却未完成的详情、表单、操作、状态或视觉项必须继续完成，
不能仅因为耗时、代码量大、想先提交或测试暂未运行就写成“后续批次”。
真实接口/授权阻塞及用户明确批准的排除项如实记录，不为追求一次完成越过安全边界。

## 不可退化的约定

- 缺值/NaN/零分母、真实0、空结果、错误与无权限分开；未知指标不填0，无身份样本不造对象行。
- 排行按对象身份合并；完整选项、服务端全局排序、总数和分页逐项核对。模拟集合须超过 TopN/一页，不能冒充真实规模；实际使用量与分配量用不同值测试。
- 查询路径和缓存都包含作用域，member 失败不能静默读取 host。配置开关、组件对象、健康状态和分类入口不是同一能力。
- 终端和日志保留独立近全屏弹窗；原生终端支持 Tab/历史/ANSI/光标/PTY，bash 不存在回退 sh，Esc 留给程序，首次输出而非握手101才算就绪，关闭释放连接。日志可使用后端 HTTP 流，不强制改 WebSocket。
- 不安装 vim 来凑验收，不创建替代高权限工具 Pod；不切换生产 GPU 模式、不改设备插件、不部署生产或执行未经授权的破坏性操作。写入测试仅在授权范围创建唯一临时对象，回读并在失败时清理，只清理自己的对象。
- 密码、token、真实 kubeconfig 不进入文档、日志、截图或仓库。真实读取与非敏感模拟下载/403分别记录。

## 验证与持续推进

`verify.py --no-e2e` 不包含显式类型检查、构建、Storybook、浏览器或生产验收；门禁自洽不证明旧能力完整。
在 console 仓库运行本批严格 `check_docs.py`；在 `kube-frontend` 按受影响包执行 typecheck/构建/测试；在 `tests/ui` 对本批相关与共享影响用例显式使用 `-n 0`。
全仓基线失败保留文件、错误、命令与影响范围，不豁免规则、删 AC 或修改并行范围掩盖失败。
全站串行 E2E、新版本地全栈到B200、实际生产/member、模拟边界分别结论，未执行写未验收。

完成整个选定单元后更新对应交付记录和能力矩阵条目，再快速选择下一个单元，重复同样闭环；不要每次重新分析全部待办，也不在多个历史计划追加同一进度。
局部阻塞时先完成该单元内其他可执行项，并记录证据、复查条件及剩余原子 ID；只有确实需要授权/决策或外部恢复才能继续时，才交接或选择一个不受影响的替代单元。不用换模块掩盖本批尚可完成的工作，不虚报全部完成。
不要自行提交或推送。用户明确要求提交后，只提交本批已核对的文件，不混入并行工作，不推送远端除非另获明确要求。

最后用中文简洁报告：本批页面与原子能力完成情况、具体测试结果及失败/skip、截图与记录链接、当前剩余项和下一步；结论不得超出实际验证范围。
