# 流程改进台账（2026-11-16）

> 目标要求「每完成一次迁移就反思如何迭代优化流程」。这份台账把**已经踩过、且已固化成规则**的经验集中记下来，
> 避免散落在各轮记录里。每条都注明**触发它的具体事故**，不是泛泛而谈。

## A. 写测试 / 改测试

| # | 规则 | 触发事故 |
| --- | --- | --- |
| A1 | **改完立刻 `--collect-only` + 跑单条**，不要攒到最后 | 一轮里连续踩了四个坑（丢缩进、多搬了 screenshot、参数没用上、属性不存在），任意一个「跑一条」就能发现 |
| A2 | **一 spec 一文件**；新增分组用 `parametrize` 扩展同一个函数 | 加第二个 `def test_` 被门禁拦下（`应恰好有 1 个测试函数`） |
| A3 | **模块级常量放在被测函数之前** | `TAB_PAGES` 定义在装饰器之后，静默只收集 37 条而不是 41 |
| A4 | **一个用例一个页面**，不要在大循环里遍历多页 | 36 页循环：任一页慢/错就整轮中止，已验证的 35 页不留证据；拆开后 189s→132s 且一次全绿 |
| A5 | **空表/无数据是另一种形状**，断言要分支 | 空表隐藏最后一列后工具栏消失，后续步骤无处可点；行数在两次读取间变化使表头比较失去意义 |
| A6 | **页签内表格要先点页签**，且等页面稳定后再点 | 懒挂载的 `TabsContent` 未激活时列表不渲染；加载中点会被随后的重渲染退回默认 |

## B. 判断失败原因

| # | 规则 | 触发事故 |
| --- | --- | --- |
| B1 | **先跑 `tools/link_health.py`，再判读失败** | 41 条用例全 ERROR，真因是 BFF 502（隧道/BFF/静态站全挂）；重建四件套后同样用例 41 passed |
| B2 | **读取失败 ≠ 不存在**，必须 failed 不能 skip | 接口 502 时用例报「集群没有 CRD」，报告上看起来像「这个集群没数据」 |
| B3 | **静态契约写太窄会制造假缺陷** | 导航契约把两层的 `apps/instances` 判成缺失；写请求契约把「把 error 传给弹窗」这种正确写法判成违规 |
| B4 | **负向验证必须先证明篡改生效** | 三次把 `probe()` 改成 `return true` 都「通过」，差点得出「自检不敏感」的结论——实际是篡改没落盘 |

## C. 改代码 / 改令牌

| # | 规则 | 触发事故 |
| --- | --- | --- |
| C1 | **定位 CSS 块用行首选择器，不用 `indexOf`** | `indexOf(":root[data-theme='light']")` 先匹配到注释里的同名文字，声明插到规则外，CSS 解析器丢掉整个浅色块，5 条用例全红 |
| C2 | **改在影响面最小的地方** | 悬停表面文字不达标，改背景（1 处）而不是改全局文字色（每处都变） |
| C3 | **先量后改** | 三个候选色值先算出四个比值再选，避免「改完看测试」 |
| C4 | **填充色不能当文字色** | `--ai-accent` 作链接色只有 2.84:1；新增文字专用 `--ai-link` |
| C5 | **修一个缺陷后，把同一根因的其它用法一次查完** | 资源页签修好后，「集群」显示行还留着同样的错误值（把 runtime id 当集群名） |
| C6 | **语义标签决定显示什么** | 标签写「集群」就必须显示集群名，塞运行时 id 会被读者当成集群 |
| C7 | **判「是不是 bug」先回旧实现核对语义**，再决定修还是保留 | 修完才去查旧 console，发现 API 路径那部分本来就是旧实现的正确规则 |
| C8 | **有意偏离旧实现要写明「偏离了什么、为什么」** | 显示层与旧 console 不同，不记录就会被后来者当成回退 |
| C9 | **改路径拼接先验证「函数输出 == 期望字符串」** | 修成员集群路径段时，helper 写错但看起来对，页面照旧 404；绕两轮才打印返回值 |
| C10 | **单集群验证不出多集群缺陷**：只在 `host` 上跑过的路径拼接，成员集群上可能全错 | 两个环境都是单集群（或只用 host），直到切到 A100 的 `xc` 才暴露 |
| C11 | **测试也会固化缺陷**：断言写错位置时，测试在 host 上永远绿 | `devops.test.ts`、`configmaps.test.ts`、`kubectl.test.ts`、`overview-completion.test.ts` 都断言过旧的（错误的）集群段位置 |
| C12 | **扫尾按症状找，不按文件找**：从错误 URL 反查调用者 | 上一轮按文件列了一遍，漏掉 `projects.ts` 里另一份 `namespacesPath`；本轮从 `limit=50` 反查到 `projectsApi` 一次命中 |
| C13 | **同一个 helper 会在多个模块被复制**，收敛到一处才算完 | `namespacesPath` / `clusterSegment` 各有 5+ 份副本 |
| C14 | **固定 sleep 的巡检会给出「看起来正常」的假结果**，必须等状态机离开 loading | 多集群巡检第一版固定等 6s，每页都报「ready / 0 行」 |
| C15 | **把人工检查变成一条可重跑的命令**，才有资格说「已验证」 | 23 页 × 2 集群靠手点是无法复现的；写成 `multicluster_sweep.py` 后一条命令覆盖 |
| C16 | **写操作必须先确认它落在哪个集群**：读对了不代表写对了 | 从成员集群页面创建的配置字典落到了主集群 |
| C17 | **不能实现的操作用「拒绝 + 说明」，绝不用「打到默认集群」** | 写路径静默丢弃 cluster 参数，把对象写进 host |
| C18 | **写验证要同时列举两个集群**，只看当前页面会被乐观刷新骗过 | 弹窗关闭像成功，实际对象在另一个集群 |
| C19 | **一条「拒绝」的修复必须配一条「允许」的验证** | 只证明 core 写被拦下，若分组写也被误拦用户就完全不能写了 |
| C20 | **断言要区分「对谁有意义」**：跨集群断言在 host 上恒真/恒假 | write-check 第一版对 host 也断言 on_host=False，必然 FAIL |
| C21 | **把多条检查合成一条带退出码的基线**，才可能被反复执行 | 读巡检 + 写检查分散时，每轮都要手工拼命令；合成 `--baseline` 后一条命令覆盖 106 次访问 |
| C22 | **基线要滤掉已知噪声，但只滤「握手」与「一次性抖动」**：认证 401 过滤，5xx 重试一次 | `session/me` 的 401 与 `configz` 的一次 503 都曾把整条基线判成 FAIL |
| C23 | **清理一类缺陷要同时扫 `apps/` 与 `packages/`** | api-client 清完后，`pages/cluster/juicefsQueries.ts` 里还留着一份手拼的旧位置 |
| C24 | **每扩一档覆盖面就会暴露新缺陷**：列表 → 深度页 → 详情页，每一档都抓到至少一处 | 深度页抓到 metrics 路径、详情页抓到 workloadPath、JuiceFS 页抓到 persistentvolumes |
| C25 | **交互类检查必须证明「交互真的发生过」**，否则全绿是假象 | 交互巡检第一版 6 页全绿，实际 4 页句柄没找到、什么都没做 |
| C26 | **SKIP 要打印出来但不计失败**：隐藏 SKIP 会把未覆盖当成已覆盖 | pods 页曾 SKIP，后来查明是作用域拼错而非无数据——**SKIP 促成了这次修正** |
| C27 | **同一个页面在不同作用域是不同的路由**，巡检要带上作用域 | 容器组列表只在 `/clusters/<c>/pods`，项目作用域下不存在 |
| C28 | **共享代码的改动必须在单集群环境回归**：多集群修好了不代表 host 没坏 | `clusterScoped`/`coreWritePath` 动的是共享路径，B200 基线 172 秒 PASS 才算数 |
| C29 | **基线的命名空间/项目是环境相关的**，换环境先确认真实存在 | 在 B200 上用 A100 的 `spaces` 项目，写检查 404，一度被误读为回归 |
| C30 | **逐项记录交互是否为真**，而不是笼统一个「通过」 | `next=False` 可能是「没得翻」也可能是「控件没找到」，两者含义完全不同 |
| C31 | **控件类型不能凭名字猜**：`select_option()` 只对原生 `<select>` 有效 | 每页条数是 Radix 组合框，报错 `Element is not a <select> element` |
| C32 | **一张页面一个干净的 page 对象**：残留菜单会让后续所有点击失效，表现为「没有句柄」 | 重构后 5 张列表全 SKIP，实际是上一张的菜单没关 |
| C33 | **5xx 要区分「上游超时」与「路径缺陷」**：前者重试，后者必须修 | 成员集群 pods 列表偶发 503，但 URL 里 `clusters/xc` 位置是对的 |
| C34 | **页面全白先看控制台第一条报错**，不要先怀疑数据/权限 | 本轮 body 长度 0，报错直接点名 MIME 类型，指向构建 base 与静态服务器不匹配 |
| C35 | **重试不能丢掉第一次的证据** | 5xx 重试后 `acted` 被重置，全绿变全 SKIP |
| C36 | **权限自检也是集群相关的**：写死的 host 路径会让按钮与真实权限不一致 | `selfsubjectaccessreviews` 没有集群段，成员集群上答的是主集群 |
| C37 | **全部页面同时坏且无失败请求 = 前端渲染阶段抛错**，先查共享组件 | 本轮两集群所有列表页 error、零 4xx/5xx、零 pageerror |
| C38 | **巡检要能发现「读到了另一个集群的数据」**，不能只看 404/error | 告警列表在 xc 上显示 host 的 71 条，state/rows/errors 三项全绿 |
| C39 | **成员集群缺能力时报错优于回退到主集群** | xc 的告警聚合接口 503，补上集群段后如实报错，而不是继续展示 host 数据 |
| C40 | **「读到了另一个集群的数据」要有可执行的判据**：host 200 而成员非 200 即 SUSPECT | 告警页全绿却显示 host 数据；`--data-identity` 现在独立复现它 |
| C41 | **每条验证结论都要绑定代码状态**（HEAD + 未提交文件数） | 共享检出里 100+ 未提交改动让整站不可用，失败基线一度看起来像提交回归 |
| C42 | **工具给的结论要用定点探针复核一次**，尤其是「页面全绿/全红」这种聚合结论 | 巡检把空白页记成 ready，据此得出「告警修复没生效」的错误结论 |
| C43 | **未验证成功的修法要回滚，不要留在仓库里** | 三种 settle 修法都没解决问题，回滚到 HEAD 版本 |
