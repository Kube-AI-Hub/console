# 权限检查的 iam 路径在 B200 上 500（2026-11-17）

## 现象

B200 八段式基线出现 **9 + 14 条失败请求**（页面本身仍渲染，0 error）：

```
500 /kube-frontend/kapis/iam.kubesphere.io/v1alpha2/selfsubjectaccessreviews
```

## 直接对比两条路径（同一账号、同一 body）

```
POST /apis/authorization.k8s.io/v1/selfsubjectaccessreviews              -> 201
POST /kapis/iam.kubesphere.io/v1alpha2/selfsubjectaccessreviews          -> 500
     no matches for iam.kubesphere.io/v1alpha2, Resource=selfsubjectaccessreviews
```

## 结论

- **B200 的 ks-apiserver 没有把 SSAR 注册进 iam 聚合 API**；原生 `authorization.k8s.io/v1` 正常。
- A100 上同一条 iam 路径可用（同轮 A100 基线 0 失败请求），所以这是**部署差异**，不是笔误。
- 这条改动目前在 `permissions.ts` 的工作区改动里（未提交），因此基线在 B200 上会红。

## 建议

权限检查要么固定用原生 `authorization.k8s.io/v1`（两环境都通），要么在 iam 路径 500 时回退到原生路径——
与「成员集群 core 组不可读时明确说明而不是回退主集群」同一个原则：**能力差异要显式处理，不能靠运气**。
